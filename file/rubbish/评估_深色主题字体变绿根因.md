## 4. 当前界面设计评估（优缺点）
**优点**
- 结构高度统一（四色同骨架），换肤成本低。
- 44×44 关闭热区满足可访问性（触控目标 ≥44px，WCAG 2.5.5）。
- 文字由纯黑改深灰（`#333`/`#1F3B2D` 等），降低大白底上的刺眼感，更"高级灰"。
- 无滚动条 + 顶部拉齐线，面板稳定、秩序感强。
- dark 草稿把主文字从 `#EDEDED` 调到 `#D9D9DE`，是对"纯白刺眼"的合理收敛。

**风险 / 待决**
1. **风格冲突**（评估点 A）：柔和极简风（阴影+圆角）vs 线框风（无阴影无圆角）必须以 §3.15.1 为准统一。
2. **令牌不一致**（评估点 B）：草稿四色 ≠ 正式 F18 令牌。
3. **CloseX 双态**：§3.15.1 要求 CloseX **硬编码** `#111`（浅色三态）/ `#E8E6E0`（dark），不随主题色变；但草稿 CloseX 用 `#C8C6C1` 等跟随主题，需核对是否违反护栏。
4. **dark 文字亮度**：草稿 `#D9D9DE` 与正式 `#E8E6E0` 不一致，落地以正式为准。
5. **green 主题的文字色本身就是绿**（`#1F2A1B`）——这是第 5 节根因的核心。

## 5. 深色界面大部分字体显示为绿色 · 根因诊断

### 5.1 核心机制
四主题共用**同一个令牌名 `--foreground`**（即文字/描边颜色）。关键事实：
- `green` 主题的 `--foreground` = **绿色**（`#1F2A1B` 正式 / `#1F3B2D` 草稿）——这是为浅绿底 `#F2F6EF` 设计的深绿文字。
- `dark` 主题的 `--foreground` = **暖白**（`#E8E6E0`）——为深底 `#262624` 设计。

两者只是"同名令牌在不同 `data-theme` 下的不同取值"。只要 dark 主题**没有正确拿到自己的那组取值**，就会回落/串到 green 的取值，于是满屏文字变绿。

### 5.2 根因（按可能性排序）

**① 主题→令牌映射错误 / 缺省回落（最可能解释"大部分字体变绿"）**
实现里 `appearance='dark'` 本应加载 dark 令牌集；若映射表有 fallthrough、键名拼错，或默认值被设为 green，dark 模式就整套加载了 green 令牌集——其 `--foreground` 为绿 → **全局文字变绿**。覆盖面广，正好对应"大部分字体"。

**② `[data-theme="dark"]` 块漏写/拼错 `--foreground`**
若 dark 作用域只覆盖了 `--background`/`--sidebar` 等，而 `--foreground` 未在 dark 块声明，则浏览器回落到级联中"下一个可用声明"——通常是 green 在更宽作用域（`:root` 默认或后声明的 green 块）写的绿色 `--foreground`。结果：深底 + 绿字。

**③ `--foreground` 被别名到 `--accent`（强调色）**
若代码写成 `--foreground: var(--accent)`，而 dark 下 `--accent` 被误设为绿（或别名错乱），文字整体染绿。

**④ Tailwind v4 `@theme` 全局令牌 + `data-theme` 作用域的特异性/顺序问题**
在 `@theme` 中定义的令牌是全局的；若 dark 用 `:root[data-theme="dark"]` 覆盖，但 green 的 `--foreground` 声明在更靠后/更高特异性处，green 取值会盖掉 dark。

### 5.3 为什么当前不是"已发生 bug"
项目内无应用主题源码；`gen_nav_proto.py` 的深色变量 accent 是蓝色且仅为原型工具。**所以这是预防式发现**——但设计架构（共享 `--foreground` + green 自带绿字）正是制造该坑的温床，M1/M5 真实落码时极容易踩。

### 5.4 修复 / 护栏建议
- **dark 块必须自包含地显式声明全部 5 个令牌**（`--sidebar/--background/--selected/--foreground/--border`），任一都不留回落。
- **各 `[data-theme="x"]` 块独立完整**，不要把 green 的 `--foreground` 设在 `:root` 默认；若必须设默认，默认应为 `light` 而非 `green`。
- **加载逻辑加断言/快照测试**：dark 主题下校验 `--foreground` 的色相非绿（或至少 `!== green 的 foreground 值`，且亮度足够高以适配深底）。
- **命名护栏**：可考虑把"文字色"与"主题强调色"彻底分开，green 的"绿"只体现在 `--selected`/`--sidebar` 等表面，绝不进入 `--foreground`，从根上消除"绿字"可能。
- 参考错误写法 vs 正确写法：

```css
/* ❌ 错误：dark 漏写 --foreground，回落到 green 的绿字 */
:root[data-theme="green"] { --foreground: #1F2A1B; --background:#F2F6EF; }
:root[data-theme="dark"]  { --background:#262624; --sidebar:#1F1F1F; } /* 缺少 --foreground */

/* ✅ 正确：每个主题自包含声明全部令牌 */
:root[data-theme="dark"]  { --sidebar:#1F1F1F; --background:#262624; --selected:#3F3F3C; --foreground:#E8E6E0; --border:#111; }
:root[data-theme="green"] { --sidebar:#E4ECDF; --background:#F2F6EF; --selected:#9CAE83; --foreground:#1F2A1B; --border:#111; }
```
