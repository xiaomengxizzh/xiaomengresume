## 一、AI 设计品味 Skills（taste 类）

**澄清**：`anthropics/skills` 官方仓库 17 个 skill 无 "taste" 命名（已逐项核验目录）；"taste-skill" 是社区俗称，核心 = anti-slop（反 AI 生成味）规则集——禁千篇一律居中标题/紫色渐变/卡片套卡片/无脑圆角/Inter 字体等。

1. **frontend-design**（官方）— github.com/anthropics/skills/tree/main/skills/frontend-design
   四条原则（主题为锚/英雄区即论点/字体排版承载性格/结构即信息）+ 3 组要避开的 AI 默认审美 + 5 步流程 + 质量底线（键盘焦点、reduced-motion）。**评级：高**——纯规则文本、React+Tailwind 契合、官方权威。
2. **Leonxlnx/taste-skill**（社区最知名）— github.com/Leonxlnx/taste-skill · MIT
   三旋钮（DESIGN_VARIANCE 布局实验度 / MOTION_INTENSITY 动效强度 / VISUAL_DENSITY 信息密度）+ 审美方向模块 + anti-slop 硬规则 + "既有项目改版审计协议"。安装 `npx skills add ...`。**评级：高**——框架无关可复制。
3. **Hayatelin/taste-skill-zh-CN**（中文版）— github.com/Hayatelin/taste-skill-zh-CN · MIT
   基于 Leonxlnx 原作（15 文件约 6800 行）；"情境触发"而非一律套用：先读页面类型/受众/品牌资产 → 输出一行"设计判读"让用户早纠偏。**评级：高（中文项目尤佳）**。
4. **Dragoon0x/taste-skills**（判断力层）— github.com/Dragoon0x/taste-skills · MIT（experimental）
   "Agents can build interfaces. They can't tell if the interface is any good."——训练视觉判断而非实现，感知/判断/分析/排版/交互七大类。**评级：中**——评审补充层。
5. **pbakaus/impeccable**（lint 级护栏）— github.com/pbakaus/impeccable · Apache-2.0
   源自官方 frontend-design；23 命令 + **59 条确定性检测规则（纯 lint 无需 LLM/API key）**——经典 AI 味清单（勿到处 Inter、勿纯黑纯灰、勿灰字压彩底、勿卡片套卡片、勿 bounce 弹性缓动）。**评级：高**——现成"丑设计拦截器"，本地零成本。
6. **emilkowalski/skills**（Emil Kowalski，Vercel/Linear 前设计师）— github.com/emilkowalski/skills · MIT
   动效建议为主（emil-design-eng/animate/apple-design）。**评级：中**——桌面文档应用动效场景有限。
7. **shadcn/ui skills** — ui.shadcn.com/docs/skills
   读 components.json 注入上下文、OKLCH 主题。**评级：中**（已手抄 shadcn，继续扩组件则升高）。

其他官方 skill（适配低，仅列名）：web-artifacts-builder（单文件 bundle，架构不符）/ canvas-design（海报）/ theme-factory（PPT）/ webapp-testing。社区膨胀同名仓库（design-taste 等）质量未核验，不优先采用。

## 五、当前项目 UI 整体评估（2026-08-11 实测，附于本报告）

> 工具链：ui_capture_full.cjs 采集 9/13 类截图 + 一次性补采编辑器真实界面（`tmp_editor_full.png`/`tmp_new_view.png`）→ doubao 视觉评估 6 张关键截图 → **impeccable detector**（新工具，静态反模式扫描）→ **culori 令牌对比度核算**（新核算脚本，4 主题）→ 代码核实 Logo 加载路径。

### P0（真实生产缺陷，dev 环境掩盖）

- **Logo 全应用破损**：`NavBar.tsx:144` 与 `WelcomeView.tsx:13` 均 `<img src="/icon.png">`（绝对路径）；生产加载为 `main/index.ts:72` `loadFile(out/renderer/index.html)`（file://）→ `/icon.png` 解析到盘根 404。**dev（vite server）下正常故此前未暴露**。6 张截图 doubao 一致确认左上角 + 欢迎卡片 Logo 显示破损占位。`out/renderer/icon.png` 存在（构建已拷贝），改相对路径或经协议加载即可修复（**仅登记，未执行**）。

### P1（视觉质量，中）

- **内容重心偏上 / 大面积留白**：首页欢迎卡、导入向导、新建视图三处 doubao 均报"内容集中上半/左上，下半大面积空白"——空态填充度不足（01_home_full 仅见欢迎卡片、无简历列表呼应）。
- **编辑器模块容器风格不统一**：上部 3 个设置分组（图片/姓名职业/标签信息）无卡片背景，底部模块为白色圆角卡片——同屏两种容器语言。
- **排版折叠面板展开内容在容器外**：白色容器仅包裹折叠标题栏，展开的设置项落在灰背景上。
- **A4 预览空态结构突兀**：头像占位下方直接接教育经历区块，无姓名/职业基础信息展示占位。

### P2（低/轻微）

- 圆角不统一（折叠栏 ~12px / 控件 ~8px / 预览卡 ~4px）；阴影不一致（仅排版折叠栏有投影）；占位文字对比度低（占位设计特征，可接受）；编辑区分组仅靠留白无边界（低）。

### impeccable 检测（新工具实测）

- 仅 2 条反模式：`styles.css:655` `transition: width`、`styles.css:821` `transition: max-height`（布局属性动画 → layout thrash，P3 级）。**零**硬编码色/字体滥用/卡片套卡片命中——令牌体系应用良好。

### culori 对比度核算（新核算）

- 4 主题 `fg/bg`、`fg/card` 全 ≥4.5（6.12–14.19）；`brand` 色相 h=273–278（蓝紫非绿）；`brand/card` ≥3（4.54–5.57）。护栏全绿。唯一观察点：green 主题 `brand/bg`=3.00 压装饰可辨阈值线。

### impeccable audit.md 5 维评分（框架套用）

| 维度 | 得分 | 依据 |
|---|---|---|
| Accessibility | 3/4 | 令牌对比度全绿（WCAG AA）、focus-visible、aria-current 已取；占位文本对比低 |
| Performance | 3/4 | main 懒加载 + renderer 代码分割（A 批已落地）；仅 2 处布局属性动画 |
| Theming | 4/4 | 全令牌化、4 主题自包含、impeccable 零硬编码色命中 |
| Responsive | 2/4 | 桌面应用 minWidth 1024 兜底，移动端非目标（定案 P3 不做） |
| Implementation Integrity | 2/4 | 容器风格不统一、折叠面板容器外、空态结构突兀 |
| **总分** | **14/20** | **Good（address weak dimensions）** |

### 评估结论（不落方案）

整体"结构稳、细节欠打磨"：令牌/主题/可访问性基础扎实（14/20 中主题与性能接近满分），短板集中在**空态填充、容器一致性、折叠面板边界**三处 + 1 个 P0 Logo 加载缺陷。截图临时产物已 gitignore 防护不入库；本评估仅登记未修改任何代码。
