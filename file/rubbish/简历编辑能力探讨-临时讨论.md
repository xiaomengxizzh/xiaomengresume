## 一、现状盘点：用户现在已能改到什么程度（基线）

| 修改维度 | 已有能力（已定案） | 程度 |
|---|---|---|
| 内容级 | 8 个 section 全部字段可编辑；富文本（summary/描述/bullet）支持加粗/斜体/列表/链接/对齐/高亮/颜色/下划线 | 完全自由（用户掌控文本） |
| 条目级 | 教育/工作/项目/技能/证书/语言 条目**新增 / 复制 / 删除**（F2 用户视角）；日期选择器、下拉框 | 增删复制 ✅，**排序未定案** |
| 版式级 | 3 套单栏模板（classic/modern/compact）+ 预设主题（`--resume-font/accent/spacing`） | L1 换皮 |
| 安全级 | F16 隐私打码（编辑态不受影响，打印态脱敏） | — |
| 撤销级 | Ctrl+Z / Ctrl+Y，50 步，500ms 防抖合并 | — |

> 一句话现状：**用户能改"内容 + 条目增删复制 + 换皮"**；不能改"条目顺序、section 显隐排序、版式细调、结构扩展、自由排版"。

## 二、用户修改程度光谱（本稿核心框架）

> 回答"用户可以进行什么程度的修改"：定义 5 级光谱，逐级给出**现状 → 建议边界 → 理由**。

| 级别 | 含义 | 现状 | 建议边界 |
|---|---|---|---|
| **L0 内容级** | 改字段文本 / 富文本 | ✅ 已完整 | v1.0 完整交付，不设限 |
| **L1 条目级** | 条目增 / 删 / 复制 / **排序** | ⚠️ 增删复制已定案，排序未落 | v1.0 加按钮排序（零依赖）；v1.1 升拖拽 |
| **L2 结构级** | section **显隐 / 排序** / 自定义 | ❌ 明确不进 v1.0（F4 L2 候选） | v1.1 做显隐 + 排序（optional 字段零迁移）；自定义 section 留 v2 受限实现 |
| **L3 版式级** | 模板 / 主题 / 间距 / 字体 | ⚠️ 预设 3 模板 × 预设主题 | v1.0 预设；v1.1 加"主题微调 UI"（取色器/字体/间距滑杆，CSS 变量已就位，成本低） |
| **L4 自由级** | 自由画布 / 真 WYSIWYG 行内编辑 | ❌ 已拒绝（F2 定案） | **永不**。理由见 §四 D4/D5 |

> 边界总原则：**用户可以自由修改"数据模型能表达的一切"；数据模型刻意不表达"自由排版"**——简历本质是结构化数据，自由排版与 ATS / 模板=打印 / 撤销栈三条铁律冲突。

## 三、候选编辑功能清单（重点：可行性 + 实现方法）

> 分四组：A = v1.0 顺手可加（低成本高价值）；B = v1.1 结构增强（L2 落地）；C = v1.x 版式/体验增强；D = v2+ 远期或明确不做。
> 可行性口径：**高** = 现有技术栈直接支持；**中** = 需小量新逻辑/新依赖；**低** = 架构冲突或工作量大。

### A 组 · v1.0 顺手可加（建议随 M1 编辑器一并落）

| # | 功能 | 用户价值 | 可行性 | 实现方法要点 | ATS/架构影响 |
|---|---|---|---|---|---|
| A1 | **条目上移/下移**（按钮版） | 经历/项目顺序微调是最高频需求，按钮比拖拽稳 | **高** | 列表条目含 `id`，store 加 `moveItem(section, id, dir)` → 数组 splice；提交级变更入撤销栈；渲染层每卡片加 ↑↓ 按钮（lucide 图标） | 无。零新依赖 |
| A2 | **空条目/缺必填校验提示** | 导出 PDF 前发现"第 3 条工作经历没写公司名" | **高** | 复用 Zod 校验（`ResumeSchema` 已有 `min(1)`）；保存/导出前 `safeParse`，失败定位到具体条目卡片并标红 + toast | 无。纯渲染层 |
| A3 | **富文本粘贴分条** | 从 Word/网页复制多行经历，自动拆成多条 bullet（高频痛点） | **高** | Tiptap `editorProps.handlePaste` / 扩展 `extendPasteRules`：检测粘贴多行文本到 `highlights` 时按换行拆分为多 bullet 段落 | 无。Tiptap 扩展，零新依赖 |
| A4 | **必填字段视觉标识** | 表单明确哪些字段是导出底线 | **高** | 表单 label 加 `*`（basics.name / 各 section 必填项），校验失败高亮 | 无 |
| A5 | **条目折叠/展开** | 经历多时表单太长，折叠提升编辑效率 | **高** | 卡片头部折叠状态存组件本地 state（不进 store）；折叠仅编辑态，不影响数据与预览 | 无 |
| A6 | **快捷键**（新增条目 / 折叠全部 / 下一个条目） | 键盘流用户效率 | **高** | 渲染进程 keydown 捕获，命令经 store 动作；不与 Tiptap 内部快捷键冲突（沿用 F3 纪律的边界） | 无 |

> A 组共性：全部是**渲染层 / store 层**能力，不动 `ResumeSchema`，不升 schemaVersion，不碰打印路径。实现成本每个 0.5–1 人日。

### B 组 · v1.1 结构增强（L2 落地，服务"改结构"需求）

| # | 功能 | 用户价值 | 可行性 | 实现方法要点 | ATS/架构影响 |
|---|---|---|---|---|---|
| B1 | **Section 显隐** | 简历可针对岗位隐藏"证书/语言"，裁剪篇幅 | **高** | `ResumeSchema` 增 optional `hiddenSections: string[]`（**仅增不改，schemaVersion 不升**，与 `targetJobDescription`/`boundJobId` 同策略，零迁移）；模板渲染时过滤；编辑侧"Section 设置"勾选 | 无 ATS 影响（隐藏=不渲染，仍是标准单栏） |
| B2 | **Section 拖拽排序** | 经历优先于教育 / 教育优先于技能，按岗位重排 | **高** | 同上增 optional `sectionOrder: string[]`（缺省 = 默认顺序 `basics→summary→education→work→projects→skills→certificates→languages`）；渲染按 order 输出；编辑侧设置面板 + 拖拽列表 | 无（标准标题顺序变化不破坏 ATS 解析） |
| B3 | **条目拖拽排序**（升级 A1） | 比按钮更顺手的重排 | **中** | 方案一（推荐）：dnd-kit（轻量、React 生态标准）；方案二：原生 HTML5 DnD（零依赖但体验糙）。拖拽结束 = 提交级变更入撤销栈 | 无 |
| B4 | **预览 ↔ 表单双向定位** | 预览里看到问题，点一下跳回对应表单卡片（F9 已有 `focusField` 概念可复用） | **高** | 预览模板每块渲染带 `data-path="work.2"`（与 F1 字段路径对齐）；点击 → store `focusField(path)` → 表单滚动定位 + 聚焦；表单输入时预览对应块短暂高亮 | 无（data 属性不进打印 CSS） |

> B 组共性：`hiddenSections` / `sectionOrder` 均为 optional 数组字段，**仅增不改、不升版本号、零迁移**，与 F9/F19 扩展同策略（见《项目功能.md》F9 落地点）。**v1.0 不预留**（保持数据模型干净，F4 L2 决策），v1.1 落地时再加。

### C 组 · v1.x 版式与体验增强（L1/L2 的"细调"补齐）

| # | 功能 | 用户价值 | 可行性 | 实现方法要点 | ATS/架构影响 |
|---|---|---|---|---|---|
| C1 | **主题微调 UI**（取色器 / 字体下拉 / 间距滑杆） | "预设主题不够，我想微调" | **高** | F4 的 `--resume-accent/font/spacing` 变量已就位；主题面板加"自定义"：accent 用 `<input type=color>`、字体用预设字体集下拉（内嵌 OFL 黑体 / 系统 fallback 链）、间距滑杆实时写 store；零组件重复 | 无（仍是单栏标准文本）。字体下拉仅列"许可安全"字体（OFL/系统 fallback，见《技术栈.md》§3.7.4 许可硬约束） |
| C2 | **头像本地导入** | 桌面场景用户必然有本地照片，当前 `photo` 是 URL 不实用 | **中** | `dialog.showOpenDialog` 选图 → 复制到 `userData/assets/<uuid>.<ext>` → `photo` 存相对路径；模板 `<img>` 渲染；PDF 导出前主进程解析相对路径为 file:// 或 dataURL。**注意**：photo 字段仍是 string，**schema 不变**；但备份/迁移要含 assets 目录（`backup:export` 范围扩展） | 无（头像 ATS 解析通常忽略，单栏头部不破坏结构）。隐私：F16 脱敏范围建议含头像（模糊化） |
| C3 | **页数指示**（第 1/2 页） | 求职者普遍在意"一页内" | **中** | 预览容器监听分页边界（ResizeObserver + 分页计算，或导出前 `printToPDF` 页数回传）；状态栏显示"共 N 页"；超页提示 | 无 |
| C4 | **一键压缩密度** | 内容多时快速缩到 1 页 | **中** | 联动 C1 间距滑杆 + 预设档位（compact/classic/modern 三档 spacing 系数）；预览实时看页数变化 | 无 |
| C5 | **跨简历复制条目** | 多份简历（投不同岗位）复用同一段经历 | **中** | store 级剪贴板（内存）：复制条目 JSON → 粘贴时 `uuid.v4()` 换 id 深拷贝插入；同应用内会话级即可，不落磁盘 | 无 |
| C6 | **技能熟练度可视化** | 技能的"了解/熟练/精通"直观呈现 | **中** | 沿用真实文本（如 `●●●○○` 或星级字符）+ CSS 装饰色；**禁止图片/图形进度条**（ATS 读不到图片） | 必须保持真实文本，装饰仅 CSS |

### D 组 · v2+ 远期 / 明确不做

| # | 功能 | 可行性 | 判断与理由 |
|---|---|---|---|
| D1 | **自定义 section**（用户自建标题的模块） | **中** | 建议 v2 **受限实现**：`customSections: { id, title, items[] }[]`（optional，v2 评估时可能升 schemaVersion）。风险 = ATS 锚点丢失（非标准标题）；缓解 = 标题白名单或默认渲染为标准条目样式。v1.x 不做 |
| D2 | **富文本表格** | **中** | **v1.x 不做**。Tiptap Table 扩展虽免费（MIT），但表格在 ATS 解析中常乱序；若 v2 做，仅限"技能矩阵"受限场景且模板渲染端单独处理。默认模板禁用 |
| D3 | **自定义模板 DSL**（L3） | **低** | v2 候选。核心难点是安全边界（用户模板 = 不可信代码，须受限 DSL + 沙箱校验）与"模板=打印"一致性，非"看懂版式"（见《技术栈.md》§3.7.3）。clean-room 禁执行不可信代码 |
| D4 | **真 WYSIWYG 行内编辑**（在预览模板上直接改） | **低** | **不做（F2 定案重申）**：编辑态=打印态难保证；F6/F10 导入需反向解析 DOM；撤销与 Tiptap 历史纠缠。折中 = B4 预览点击跳转已提供 90% 体验 |
| D5 | **L4 自由拖拽排版**（Canva 式） | **低** | **非目标（F4 定案重申）**：工作量大、与"模板=打印"冲突、简历本质是结构化数据不需要自由画布 |
| D6 | **多栏 / 图文混排模板** | **低** | **不做**：ATS 最大风险源（双栏解析乱序、图片化标题）；与"所有内置模板默认兼容 ATS"设计保证矛盾 |

## 四、数据模型影响一览（哪些能力动 schema、哪些不动）

| 能力 | 动 schema？ | 方式 | schemaVersion |
|---|---|---|---|
| A1–A6（条目按钮排序/校验/粘贴分条/折叠/快捷键） | ❌ | 纯 store / 渲染层 | 不变 |
| B1–B4（section 显隐/排序/条目拖拽/双向定位） | ⚠️ | + `hiddenSections?: string[]`、`sectionOrder?: string[]`（optional，**仅增不改**） | **不升**（与 F9 `targetJobDescription`、F19 `boundJobId` 同策略，见《项目功能.md》F19） |
| C1–C6（主题微调/头像/页数/密度/跨简历复制/技能可视化） | ⚠️ 仅 C2 | C2 头像路径语义扩展（URL→本地相对路径），字段仍是 string；其余全在 store/渲染层 | 不变 |
| D1（自定义 section） | ✅ | + `customSections`（v2 评估，可能升版本号走 `migrate()`） | v2 定 |
| D2–D6 | ❌ | 不做 | — |

> 结论：v1.0 的编辑能力**零 schema 变更**；v1.1 的 L2 结构增强**仅增两个 optional 数组字段、不升版本号、零迁移**——完全符合《项目规范.md》§4.2"schema 版本化"纪律与 F4"数据模型保持干净"决策（v1.0 不预留，v1.1 再加）。

## 五、建议路线图（编辑能力视角）

| 版本 | 编辑能力交付 | 呼应里程碑 |
|---|---|---|
| **v1.0** | L0 内容级完整 + L1 条目增删复制 + **A1 按钮排序** + A2–A6 + L3 预设模板/主题 + F16 脱敏 | M1/M2（F2/F3/F4/F16） |
| **v1.1** | **B 组全部**（L2 结构级：section 显隐/排序、条目拖拽、双向定位）+ C1 主题微调 + C5 跨简历复制 + F19/F20 | M3 |
| **v1.2** | C2 头像本地导入 + C3 页数指示 + C4 一键压缩 + 导入四路（F6/F10/Word/JSON） | M4 |
| **v2** | D1 受限自定义 section + D3 自定义模板 DSL（评估） | 远期 |

> 优先级理由：A 组全是"编辑高频痛点 + 零 schema 变更 + 零新依赖"；B 组是用户明确表达过的"改结构"需求且代价可控（optional 字段）；C 组提升精致度但不影响核心闭环；D 组触碰 ATS / 安全 / 架构边界，必须远期谨慎。

## 六、关键边界判断汇总（一句话版）

1. **内容修改**：完全自由，用户掌控一切文本（AI 只辅助，禁一键生成）。
2. **结构修改**：条目级 v1.0（按钮）→ v1.1（拖拽）；section 级 v1.1（显隐/排序）；自定义 section v2（受限）。
3. **版式修改**：预设模板 v1.0 → 主题微调 UI v1.1（CSS 变量已就位，成本低）。
4. **不做清单**：自由画布（L4）、真 WYSIWYG、多栏/图文混排、图片化技能条——全部与 ATS 或"模板=打印"冲突，文档化理由防走回头路（可入《技术栈.md》ADL）。
