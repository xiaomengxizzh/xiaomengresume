# xiaomengresume 项目实现计划（一页式作战图）

> **文档定位**：本项目的**唯一实现总览**。回答三个问题：① 要做哪些功能；② 哪些技术栈已定案、哪些还没定；③ 按什么顺序做。
> **定稿日期**：2026-08-05
> **配套文档**：细节看《功能需求清单.md》（做什么）、《技术栈.md》（怎么做）、《项目介绍.md》第七节（文档规则）

## 〇、一句话

**开源免费 · 离线本地桌面简历编辑器（Electron）**：左边填表单、右边实时预览，能换模板、导出矢量 PDF、导入旧简历（三步核对）、BYOK 用 AI 辅助润色/查语法/算匹配度。数据全在本机，无水印无订阅。

**三个版本闭环**：
- **v1.0（1–1.5 个月）**：编辑 → 预览 → 导出 → 脱敏分享（核心闭环，先出可用版本；所有内置模板默认兼容 ATS）
- **v1.1（+）**：AI 辅助三件套（润色 / 语法 / 匹配度打分）
- **v1.2（+）**：导入（PDF / 图片 / Word / JSON）

## 四、文档填入规则（速查版）

> 详细治理规范见《项目介绍.md》第七节。这里是最常用的几条，照做即可。

**1. 文档放哪**：所有 `.md` / `.html` 一律进 `file/` 目录；缓存/二进制产物（tar.gz 等）留根目录。

**2. 内容写进哪（按主题，不新建文件）**：

| 内容主题 | 写进哪个文件 |
|---|---|
| 项目定位 / 信任承诺 / 治理 / 文档规则 | `项目介绍.md` |
| 技术选型 / 架构 / 依赖 / 里程碑 / 风险 | `技术栈.md` |
| 功能需求 / 实现框架（F1–F16） | `功能需求清单.md` |
| **实现总览 / 定案状态 / 待拍板清单** | **`项目实现计划.md`（本文）** |
| 导入专项（F6/F10） | `导入功能技术方案.md` |
| 竞品 / 用户反馈 | `竞品与用户反馈调研.md` |
| 用户操作视角 / 界面行为 | `用户操作视角功能描述.md` |
| 界面线框 / 原型 | `原型线框图.html` / `导航交互原型.html` |
| 实现纪律 / 踩坑经验 | `开发经验教训.md` |
| 依赖缓存 / 构建产物 | `依赖缓存说明.md` |
| 可行性 / 评估 | `项目评估报告.md` |
| 一切进展流水（唯一日志归口） | `log.md` |
| 并行草稿（阶段闸门期间） | `file/draft/`（串行合并后删除） |
| 与项目无关的临时过程文件 | `file/rubbish/`（随手清理，不归档） |

**3. 三条硬规则**：
- **不新建孤岛文档**：新 md 必须能挂到某个主文档索引下，否则先写进 `log.md` 登记。
- **不重复造文件**：同主题内容写进对应分区文件，**不要每次对话新建 md**。
- **每次实质进展必记 log**：带日期追加到 `log.md`（新增/修改文档、定决策、完成里程碑都要记）。
