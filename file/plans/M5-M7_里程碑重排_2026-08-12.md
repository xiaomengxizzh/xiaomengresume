# M5/M6/M7 里程碑重排（2026-08-12 定案）

> **定位**：里程碑框架总计划（定义/范围/验收/依赖），**非细颗粒执行手册**——具体批次在执行前单独出计划。
> **背景**：原里程碑只到 M5（发布）。用户拍板：功能先行、**打包最后**——原 M5 拆为「功能收尾（M5）+ 增强（M6）」，打包独立 M7（M6 功能实现会影响打包产物，如字体导入/自定义主题/新依赖，先功能后打包避免返工）。
> **真相源**：《项目实现情况.md》§三 里程碑路线表（本文与之一致）。

## 版本闭环（重排后）

- **v1.0** = M0–M2（编辑→预览→导出→脱敏分享核心闭环）+ M5（应用功能收尾，设置/外壳/日志完整）+ M7（打包发布）——M6 增强项按验收情况决定进 v1.0 或 v1.1
- **v1.1（+）** = M3 剩余（已落）+ M6 未进 v1.0 的项
- **v1.2（+）** = M4 导入（已落 M4a/M4a.1）
- **v2** = L3 自定义模板（硬骨头，前清标签架构债）

## 事项归属映射（A–G 全清单 → 新里程碑）

- **M5**：B1–B5、B8–B10、D1–D5、C1–C8
- **M6**：A1–A4、E1–E2、D6
- **M7**：B6（F14）、B7（F15）、C9（Linux 字体）
- **延后**：F 组（v2：L3 自定义模板/AI 模板助手/font-list 枚举）、G 组（标签重构/worker 化/sqlite）

## 关键依赖链

```
M5（纯功能） ── 真机验证批（M5-V 一次本机会话）
M6（vision 卡真机视觉模型；图片导出卡真机 GPU，可顺带 M5-V 同机会话验证）
M7（卡 M5/M6 验收 + Release 前置）——打包最后，功能稳定后再打
```
