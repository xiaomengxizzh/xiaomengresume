# PDF 简历导入适应性测试集 · 执行计划（2026-08-12）

> 目的：建可复现的 PDF 简历测试集 + 天池三级加权 F1 评测，量化 `rules.ts`（B 档本地规则）对不同版式 PDF 的字段识别质量；A 档样本保留待后续。

## 目标与产出

1. `material/import-cases/` 测试集（s1 自造 4 + s2 开源 ~20 + s3 真实 17，均配 `expected.json`）
2. `scripts/import_bench.mjs` 评测脚本（天池三级加权 F1）
3. 报告 `file/rubbish/import-bench-2026-08-12.md`：结果表 + 版式适应性结论 + rules.ts 改进建议 + badcase 清单

## 关键决策（用户 2026-08-12 定）

- S2 只留**中英**文，韩文/西语删除；每仓库取代表样本（同模板配色去重）→ ~20 份
- S3 用 **LinkedIn parser 12 份 + bjherger 5 份**（本地 + 假 PII 匿名化，gitignore 不入库）；弃用爬虫渠道（形态不匹配 + 合规红线）
- 评测**只测 B 档**（A 档样本保留后续 `XM_AI_KEY=1` 对比）；expected.json 按 B 档当前可识别字段标注
- 评测指标 = **天池三级加权 F1**（单值精确 / 列表多集 / 长文本字符重叠）
- 人工走查：抽样 3-5 份走三步核对向导（用户本机 GUI）
- 评测脚本放 `scripts/`（工具层，与 docs-tool.py 同级先例）；**不做 git 分支隔离**（main 直做，测试集纯增量目录，主程序零改动）

## 执行批次

| 批 | 内容 | 验收 |
|---|---|---|
| 1 | 目录骨架 + gitignore（s3/.src-tmp）+ README + 本计划落盘 | 结构就绪，s1/s2 跟踪、s3/.src-tmp 忽略 |
