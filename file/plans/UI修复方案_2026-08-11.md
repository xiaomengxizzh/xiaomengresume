## 十一、迭代深化机制

- **每批 = 一个迭代点**：批内步骤完成 → 验证门（截图 + doubao + impeccable 复扫 + culori[涉色] + material 对比 + G.7 自检[含 O5 架构铁律 8-13 勾选]）→ 通过则 commit 进入下批。
- **偏差处理两路**：验证门发现偏差 → a) 属本批可修 → 回批修正后重跑验证；b) 跨批/需定案 → 登记「遗留」并注明归属批（如 axe 新发现 → Batch 3/4 消化）。
- **跨批反馈**：Batch 2 的 axe 基线结果反向约束 Batch 3（可达性改动不得引入新违规）；Batch 3 的 material 对比结论若暴露新问题 → 追加登记（不扩批，纳入后续维护）。
- **度量（⑬）**：Batch 4 执行前后记录 C6 动画行为对比（截图序列/手动验证记录）；Batch 0 记录 axe-core 安装路径选择（R2 分支落点）。
- **收口**：全部批次完成后统一 G.7 自检 + selfcheck + 三文档同步核对 + 记忆/日志归档；临时产物清理征求用户同意后执行。

## 十二、执行顺序与回滚策略

- **顺序**：Batch 0 → 1 → 2 → 3 → 4（严格依赖：Batch 2 前置 O1 补采；Batch 3 前置 B4 定案文档更新；Batch 4 独立）。
- **回滚**：每批独立 commit（规范 message，禁 --no-verify）→ 单批失败可 `git revert <commit>`，不影响其他批。
- **风险闸门**：Batch 3 涉定案更新 + 布局重构，是最高风险批——执行前单独过一遍 R3/R4/R6/R11 分支预判 + 用户确认 B4 定案文档措辞。
