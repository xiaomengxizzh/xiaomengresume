## 一、MagicResume（JOYCEQL/magic-resume，React+Zustand+Tiptap，体量与我们最接近）

### 1.1 排版数据模型：一个扁平开关袋 GlobalSettings（src/types/resume.ts L128-143）

```ts
export type GlobalSettings = {
  themeColor?: string;        // 主题色（12 色板 THEME_COLORS）
  fontFamily?: string;
  baseFontSize?: number;      // 正文（px）
  subheaderSize?: number;     // ★ 副标题独立字号（我们缺）
  pagePadding?: number;
  paragraphSpacing?: number;
  lineHeight?: number;
  sectionSpacing?: number;
  headerSize?: number;
  useIconMode?: boolean;      // ★ 图标模式开关（联系方式 icon 显隐，我们缺）
  centerSubtitle?: boolean;   // ★ 条目头几何开关 1（见 1.2）
  flexibleHeaderLayout?: boolean; // ★ 条目头几何开关 2
  autoOnePage?: boolean;      // 自动一页纸（≈我们 fitToPage）
  pageBreakLinesVisible?: boolean; // ★ 预览分页参考线（我们有 A4 辅助线，无分页线）
};
```

`GlobalSettings` 挂在每份简历（`ResumeData.globalSettings`）上，**所有模板共享这袋设置**——模板不拥有排版参数，模板只定义"结构长相"。

### 1.2 核心机制：两个布尔开关组合出四种条目头几何（templates/classic/sections/ExperienceSection.tsx）

```tsx
<div className="flex items-center gap-2">
  <div className={`font-bold ${flexLayout ? "" : "flex-[1.5]"}`}>{exp.company}</div>
  {centerSubtitle && (
    <div className={`${flexLayout ? "ml-[16px]" : "flex-1"}`}>{exp.position}</div>  // 副标题入行
  )}
  <div className={`shrink-0 ${flexLayout ? "ml-auto" : "flex-1 text-right"}`}>{date}</div>
</div>
{exp.position && !centerSubtitle && <div>{exp.position}</div>}                      // 副标题落行
```

| centerSubtitle | flexibleHeaderLayout | 效果 |
|---|---|---|
| false | false | 公司＋日期（各 flex 弹性两端），职位落下一行 |
| true | false | 公司｜职位｜日期 三列弹性均分（职位居中区域） |
| true | true | 公司＋职位（ml-16px 紧随）＋日期（ml-auto 靠右）← **用户本次要的就是这个** |
| false | true | 公司＋日期同行两端，职位落下一行（紧凑头部） |

**启示**：不给"位置"做 N 枚举，而给**两个正交布尔开关**（进得来一行 / 排得松不松），组合出全部几何且每个开关语义单一。我们现有 `subtitlePosition: below|inline` 相当于该矩阵的 (false,false) 与 (true,true) 两角，缺中间两态与 `subheaderSize`。

### 1.3 模板体系：模板=文件夹（9 套：classic/modern/elegant/creative/editorial/left-right/minimalist/swiss/timeline）

- 每模板一个 `config.ts`（`ResumeTemplate`：colorScheme/spacing/basic.layout/availableSections）+ 一个 `sections/` 目录（每节一个小组件，classic 全模板仅 545 行）。
- 模板间**共享** shared/SectionWrapper、shared/CertificatesSection。
- `SectionWrapper`（shared/SectionWrapper.tsx，40 行）：`onClick→setActiveSection(sectionId)` + hover 高亮 + `data-resume-section-id`——**纸面直操**：点预览块=选左侧编辑面板对应节。
- 条目动画用 framer-motion `layout="position"`（增删条目自动位移）。
- `basic.fieldOrder?: BasicFieldType[]`：联系方式字段可排序/显隐/自定义（我们 TagsBlock 已有 6/8 自定义，但无字段级排序）。
- 导出：`utils/export.ts` html2canvas + jsPDF（**栅格截图**，文字不可选、体积大）——**不采纳**，我们 printToPDF/打印管线是矢量。
- 预览缩放：`preview/index.tsx`——MM_TO_PX 算 A4 像素 + `useAutoOnePage` 出 `scaleFactor`（`transform: scale()` + `width: 100/scale %` 补回），MutationObserver+ResizeObserver 双监听测内容高（与我们 fitToPage 的 ResizeObserver 同思路，多一个 mutation 监听）。

### 1.4 用户改排版的路径（编辑器侧）

`SidePanel.tsx`（814 行）分组暴露：字体族下拉 / 字号滑杆（baseFontSize、subheaderSize、headerSize 三档独立）/ 行高滑杆 / 间距滑杆 / **Switch 开关组**（centerSubtitle、flexibleHeaderLayout、useIconMode、autoOnePage、pageBreakLinesVisible）。**所有控件写 `updateGlobalSettings({...})` 单点入口 → zustand persist（localStorage/IndexedDB）**。→ 我们 LayoutBar 就是它的雏形，差别只在 MagicResume 把「几何开关」也放进了同一袋。

## 二、Reactive Resume v5（AmruthPillai/Reactive-Resume，自由度天花板；v4→v5 已大重构）

### 2.1 元数据分层（packages/schema/src/resume/data.ts，747 行 zod）

```
resume.metadata = {
  template: enum(20 模板：onyx/pikachu/gengar…Pokémon 命名)   // 模板=结构长相
  layout: { sidebarWidth: 10-50%, pages: [ { fullWidth, main: sectionId[], sidebar: sectionId[] } ] }
  page:   { marginX/marginY(pt), gapX/gapY(pt), format: a4|letter|free-form, locale,
            hideLinkUnderline, hideIcons, hideSectionIcons }
  design: { colors: {primary,text,background}(rgba), level: {type: hidden|circle|square|rectangle|rectangle-full|progress-bar|icon, icon} }
  typography: { body: {fontFamily, fontWeights[], fontSize 6-24pt, lineHeight}, heading: {…}, hyphenation }
  styleRules: 用户样式规则（见 2.2）
  stylesheet: 语义 CSS DSL（见 2.4，power-user 逃生舱）
}
```

**关键观念**：`layout.pages` 把「哪些节进哪一页、哪一栏」变成**显式 ID 数组**——多页与分栏都是纯数据，拖拽=改数组。这是"用户自由改排版"的极限形态。

### 2.2 StyleIntent 规则系统（data.ts styleIntentSchema + style-rules.ts，74 行）

- **槽位枚举（15 个）**：`section / heading / item / text / secondaryText / link / icon / level / richParagraph / richList / richListItemRow / richListItemContent / richLink / richBold / richMark`——渲染器在语义节点上声明 slot，规则按 slot 命中。
- **受限样式子集 StyleIntent**（不是任意 CSS）：color/bgColor/borderColor/opacity/fontSize(6-48)/weight/style/lineHeight/letterSpacing/textDecoration(+Style)/textAlign/textTransform/padding 四向(-72..72)/margin 四向/rowGap/columnGap/borderStyle|Width|Radius——每个值都有 clamp 区间，**可安全翻译成 React-PDF style**。
- **作用域 + 特异性合并**（resolveStyleIntentForSlot）：

```ts
const specificity = { global: 0, sectionType: 1, sectionId: 2 }
// 过滤启用且 slot 命中的规则 → 按特异性升序 → Object.assign 后者覆盖前者
return Object.assign({}, ...bySpecificity.map((rule) => rule.slots[options.slot]))
```

→ 用户可以「全局把日期改灰」+「只把工作经历的日期改红」两层规则共存、确定性合并。

### 2.3 模板=薄壳 + 语义节点（packages/pdf/src/templates/onyx/OnyxPage.tsx，209 行）

```tsx
const { style: semanticPageStyle } = useResolvedNode(semanticNodeKeys.page(pageNumber));
<Page style={composeStyles(styles.page, pageMinHeightStyle, semanticPageStyle)}>
  <SemanticRegionView region="main" style={composeStyles(styles.sectionGroup, {rowGap: metrics.sectionGap})}>
    {mainSections.map(s => <Section key={s} section={s} placement="main" />)}
```

- 模板提供**基础样式槽表**（createBaseTemplateStyles + 模板自己的 colors/roles），用户规则/语义样式经 `useResolvedNode` 解析后 `composeStyles` 叠加——**同一棵树，三层来源**（模板基线→styleRules→stylesheet）。
- `getTemplateMetrics(page)`：pt 单位统一（margin/gap→padding/rowGap），一处换算全模板共用。
- 节级 DNA（baseSectionSchema，**每个 section 自带**）：`title(任意改)/icon(Phosphor 名|'none')/columns:1-6(跨几列)/hidden/showHeading/keepTogether(整节不跨页拆)/startOnNewPage`——排版单元级自由度全在数据里。
- PDF 渲染 = **@react-pdf/renderer（服务端矢量）**；另有独立 ATS 管线（packages/resume/src/ats + ats-pdf：JD 分析/ATS 规则/纯文本导出）。

### 2.4 语义 CSS DSL（packages/resume/src/stylesheet/，约 25 个文件）

自带一个**迷你 CSS 编译器**：`parse/cascade/specificity/selector/serialize/diagnostics/limits/version` + 注册表（`PROPERTY_REGISTRY_V1`、`SEMANTIC_REGISTRY_V1`（节点种类+模板部件）、`SYSTEM_VARIABLE_REGISTRY_V1`）。样式源字符串以 `@version 1;` 开头（版本化！解析失败有诊断码）。这是给高级用户的完全逃生舱，普通用户走 styleRules/开关。

## 五、本项目改造路线（结论）

### P1 低风险高 ROI（下批可做）
1. **条目头几何对齐 MagicResume**：`subtitlePosition` 从二值扩为「位置：下方/行内紧随/行内居中」+ 新增 `subheaderSize`（副标题独立字号滑杆）。UI 全进 LayoutBar；schema 仅增不改。
2. **节级 DNA 最小集**（借 RR baseSectionSchema，取子集）：`layout.sectionMeta?: Record<sectionId, {title?: string; columns?: 1|2; keepTogether?: boolean}>`——节标题改名 + 技能/证书等可 2 列排 + 整节不跨页（配合我们自动一页纸）。渲染点 ResumeBody 各 section renderer 已集中，改动可控。
3. **页面参数拆分**：`pageMarginX/Y` + `sectionGapX`（现只有单一 pagePadding）；预览/PDF 同源。
4. `useIconMode` 式联系方式图标显隐（我们标签已有 icon，加全局开关）。

### P2 中期（需拍板后再动）
5. **typography 对象化**：body/heading/subhead 三档 `{family, weights[], size, lineHeight}`，替代散参（迁移注意兼容旧 layout 字段）。
6. **StyleIntent-lite 规则**：slot 先取 5 个（section/heading/item/secondaryText/date）× 作用域 2 层（global/sectionId）+ 受限样式子集 + specificity 合并——RR 的 resolveStyleIntentForSlot 74 行可直接作蓝本；ResumeBody 已有 path/sectionId 语义锚点。UI 需要「样式规则」面板，工作量显著。

### P3 远期/不采纳
7. 语义 CSS DSL/多页 pages 编排/free-form：与我们「单页+自动一页纸」产品哲学冲突，观望。
8. **不采纳** html2canvas 栅格导出（我们矢量更强）；不采纳服务端 @react-pdf（打印管线零服务已成立）。

### 铁律核对
- 全程 schema 仅增不改；新字段过三文档同步（F4/技术栈/功能）；P2 规则系统属"架构决策"需先拍板。
- 每批 bench（导入侧不受影响）+ 排版侧建议新增"模板快照测试"（renderSnapshot per 配置组合）防回归。
