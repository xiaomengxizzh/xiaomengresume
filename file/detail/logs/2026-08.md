### 2026-08-05 — L3 自定义模板难点 + 「AI 识别能否解决」边界
- **用户追问**：L3 自定义模板的问题，以及用 AI 识别能否解决。
- **L3 本质难点**（写入《技术栈.md》3.7.3）：① 安全边界（clean-room 禁执行不可信代码，只能走受限声明式 DSL + 沙箱校验，不能让用户写任意 HTML/CSS/JS）；② 渲染一致性（须守"模板=打印"，任意版式打破字段映射）；③ 数据映射回写（区块须绑回 F1–F17 字段模型）；④ 维护成本。难点在"安全 + 一致性"，不在"看懂版式"。
- **AI 识别边界**：F6/F10 的 AI 识别产出的是**数据**不是**版式**，解决录入而非自定义模板；视觉模型可"看懂参考图→推荐最像的预设模板+微调主题"（把 L3 降级为 AI 增强的 L1/L2，最推荐）；AI 可辅助生成**受限 DSL** 但仍过沙箱，安全边界不变。**结论**：AI 不解决 L3 本质矛盾（沙箱+一致性），只把"写 DSL"变轻松，没把"沙箱"变没；真·任意上传 HTML 模板安全渲染仍是 v2 硬骨头。

### 2026-08-05 — 模拟器定位坐标系 bug 修复（第 7 轮）
- **用户反馈**：互动模拟界面中，选中热区的蓝色边框与分区选项错位；右侧分区 overlay 大小与周围线框不匹配。
- **根因（数学验证）**：`.hot` 与 `.main-overlay` 的百分比坐标（如 `left:4.71%; top:17.39%`）以 `.wf` 容器为参照系，但 `.wf` 带 `padding:18px`，而 SVG 以 `width:100%` 只渲染到内容区（宽度 = wf 宽 − 36px）→ **两个参照系宽度不一致**，导致热区/overlay 整体偏右偏下且尺寸偏大。坐标数值本身精确（4.71%×680=32、17.39%×460=80，命中 SVG 内 x32/y80 的「简历」模块），错位纯属 CSS 参照系问题。
- **修复**：`gen_nav_proto.py`——`.wf` 内新增 `.canvas{position:relative}`（无 padding）作为定位容器，SVG 与 `.hot`/`.main-overlay` 共享同一参照系；CSS `.wf` 移除 `position:relative`、`.wf svg` 改为 `.canvas svg`。重跑脚本重新生成《导航交互原型.html》。
- **验证**：13 屏 / 12 svg；s-main 的 canvas 内含 1 svg + 3 热区 + 1 overlay；结构平衡。
- **经验沉淀（已写入 .workbuddy 记忆）**：SVG 上叠加可点击热区时，热区必须与 SVG 处于同一无 padding 的定位容器，否则 padding/border 会破坏百分比对齐——这是交互原型实现的通用陷阱。
