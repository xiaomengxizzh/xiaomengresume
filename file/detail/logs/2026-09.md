### 2026-09-08 — web 端局域网 http 崩溃修复（crypto.randomUUID 非安全上下文缺失）

- **根因**：`crypto.randomUUID` 仅在安全上下文（https/localhost）暴露；用户经 `http://<局域网IP>:4173` 访问上线版 → 导入向导"确认写入"时 store 生成简历 id 抛 `crypto.randomUUID is not a function`（渲染端共 16 处调用点：store/编辑器/岗位/导入等）。
- **修复**：`src/renderer/src/lib/uuid.ts`——`safeUuid`（原生可用则透传，否则 `uuidV4FromGetRandomValues` 按 RFC4122 v4 模板生成，`crypto.getRandomValues` 全上下文可用）+ web 垫层（installWebElectronAPIMock）启动时打 `crypto.randomUUID` 实例级 polyfill，16 处调用点一次覆盖，产品代码零改动；Electron 不受影响（dev localhost / prod file:// 均为安全上下文）。
- **踩坑复盘（重要）**：polyfill 值**不可绑 `safeUuid`**——其"原生可用则透传"判断在 polyfill 就位后看到的是自身 → 无限自调用（用户侧将表现为 `Maximum call stack size exceeded`）。本机非安全上下文实测抓到 `Crypto.lc` 递归堆栈后改为绑纯兜底实现 `uuidV4FromGetRandomValues`。
- **连带改进**：parse-core 的 PARSE_FAILED 透出底层消息（本次靠它定位到"E2E 样例被 vite build 清空 outDir 删除 → fetch 拿到 SPA 回退 HTML → pdf.js Invalid PDF structure"的测试假象）。
- **验收**：uuid 测试 2 例（原生路径 + 模拟非安全上下文兜底路径，v4 格式与唯一性断言）+ 导入/开发层 82 测试全绿，typecheck/lint 绿；**真机 E2E（`http://10.17.217.221:4173`，isSecureContext=false）**：注入自己的 PDF → 三步向导字段完整 → 确认写入 → polyfill 生成的合法 v4 id 落盘 → 编辑器打开，全程无崩溃。
