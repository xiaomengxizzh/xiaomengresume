# F2 · 编辑器（混合范式）— M1

> 本文件由 `scripts/split_docs.py` 从《项目功能.md》拆分（2026-08-08 路由化定案）；真相源 = 本文档。

### F2 · 编辑器（混合范式）— M1
- **需求**：可编辑一份完整结构化简历，所见即所得地预览。
- **实现框架**：`EditorPane` 左/上表单区（shadcn Input/Textarea/DatePicker/Select + `<TiptapField>` 富文本控件，仅 description/summary）；`PreviewPane` 右/下实时消费 store；共享 `useResumeStore`（Zustand）。编辑态 DOM ≠ 打印态 DOM，通过数据模型解耦。
- **用户视角**：面对的是**结构化表单卡片**而非整页 Word——基本信息卡片（姓名/电话/邮箱/所在地/网站）、教育/工作/项目/技能/证书/语言各 section 子卡片（+新增/复制/删除、日期选择器、下拉框）、富文本字段内嵌小型编辑器（加粗/斜体/列表/链接）。输入即右侧实时预览。
- **定案依据（P0 三选项对比，已选混合）**：混合 = 左/上表单 + 右/下实时模板预览，导出一致性强（模板=打印）、AI 导入天然有字段可填、撤销分工清晰；纯 WYSIWYG 的「编辑态=打印态」难保证且 F6/F10 需反向解析 DOM，拒绝；纯表单最稳但缺所见即所得，备选。混合的代价：自由美术排版弱（L4 不做）——简历本质是结构化数据，本来不需要自由画布。

#### F2 数据路径体系（2026-08-07 增补 · 三合一核心资产）

> 统一「数据路径」字符串标识简历任意可编辑元素，**服务 F3 撤销栈 / F7-F10 AI 定位 / 预览反查三合一**。M1 落码即建，后续消费方直接复用。

```ts
// 数据路径示例
'basic.name'                     // basics 字段
'basic.customFields[0]'          // 自定义字段条目
'education[1].description'       // 列表条目富文本
'work[0].highlights[2]'          // 亮点数组元素
'layout.themeColor'              // 排版参数（F4 修订 per-resume）
```

- **规则**：路径从 section 名起，数组用 `[index]`；富文本定位到**字段级**（不做词级内容寻址——Tiptap selection 映射复杂度不引入 v1）。
- **消费方**：F3 撤销快照 diff 记录"哪条路径变了"；AI 输出（润色/语法/打分）精确落位"改/查了哪段"；预览反查点击 → 左侧定位。
- **预览 DOM 打标**：模板组件渲染时给元素挂 `data-rm-path`（编辑态 DOM ≠ 打印态 DOM 的红利——预览 DOM 可自由加交互标记，打印走模板纯渲染不受污染）。

#### F2 预览反查（2026-08-07 增补）

- **交互**：右侧预览 hover 显示浅色描边（可定位暗示）→ 点击 → 左侧表单滚动到对应卡片（`scrollIntoView`，**block: 'nearest'**——2026-08-07 由 'start' 改为 'nearest'，目标不可见才滚动、不强行拉顶，避免点击编辑时界面整体上移）+ 高亮闪烁；折叠 section 先展开。**定位 + 高亮即可，不强制聚焦输入框**；空字段占位符同样可点击定位。
- **粒度**：M1 尾 = section 级（点"工作经历"整块跳工作区，低成本高感知）；M2 = 字段/条目级（预览 DOM 细化打标）。
- **反向联动**（M2+）：左侧聚焦时右侧对应元素闪烁。

#### F2 编辑区固定头滚动（2026-08-08 定案）

- **形态**：`.editor-pane` 改 `display:flex; flex-direction:column`，新增 `.editor-scroll-body`（`flex:1 1 0; min-height:0; overflow-y:auto`）承接滚动；`.layout-bar`（排版条）改 `flex-shrink:0` **固定头部**（弃 sticky——sticky 在用户机器未钉住，scrollIntoView 把滚动传导到 body，顶部功能区被滚出屏幕）。
- **scrollIntoView 归位**：滚动作用域为滚动体，不触发 body 滚动（修复点击分区时顶栏/排版条消失）。
