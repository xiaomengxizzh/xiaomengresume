# F11 · 持久化与设置 — M1/M5

> 本文件由 `scripts/split_docs.py` 从《项目功能.md》拆分（2026-08-08 路由化定案）；真相源 = 本文档。

### F11 · 持久化与设置 — M1/M5
- **需求**：本地保存多份简历 + 应用设置，可备份、可副本。
- **实现框架**：简历 → `userData/resumes/<id>.json`（版本化，支持新建/重命名/复制/删除）；设置（语言/默认模板/主题/更新偏好）→ `electron-store`；自动保存防抖 + 启动恢复。**数据安全三件套（已拍板入 v1.0）**：崩溃恢复（启动检测未正常退出的临时文件）+ 自动备份（每份简历保留最近 N 份 `.bak`）+ 导出备份（设置页「导出全部数据为 zip」）。
- **用户视角**：顶栏「文件 → 新建/打开/复制/重命名/删除」；多份简历并存（每份一个本地 JSON）；底栏显示「已保存 / 保存中」；启动恢复上次编辑的简历（**2026-08-07 用户拍板：启动先进「简历」欢迎页，数据预加载但不自动切入编辑器**，用户从欢迎页主动进入；详见 §3 启动恢复说明）。

#### F11 持久化与数据安全三件套落地点（WP-P5 · P 阶段定案）

**1. 简历存储（版本化 JSON）**

- 路径：`userData/resumes/<id>.json`，`<id>` 为 uuid v4（见《技术栈.md》§3.14 工具库 `uuid`）。
- 文件结构：单份简历 = `ResumeSchema` 序列化结果，首字段 `schemaVersion`（见《项目规范.md》4.2「schema 版本化第一天开始」）。M1 起写入 `migrate(data)` switch-case，读入时若 `schemaVersion` 低于当前版本按 case 顺序迁移到最新。
- 生命周期操作（文件级，由主进程 `src/main/files/resume-store.ts` 承载，经 IPC 暴露）：
  - **新建**：生成 uuid + 空白 `ResumeSchema`（默认 `schemaVersion=1`）→ 写入 `<id>.json`。
  - **重命名**：仅改展示名（`ResumeSchema.basics.name` 或侧栏别名），文件不变；若需改文件名 id 则原子写新文件 + 删旧文件。
  - **复制**：深拷贝 JSON 并赋新 uuid → 写 `<newId>.json`。
  - **删除**：`fs.unlink(<id>.json)` + 同步删除其 `.bak` 序列（见第 3 点）。
- 落码要点：所有文件 IO 在主进程（架构铁律 1）；渲染进程只持 `useResumeStore`（Zustand）内存态，状态条「已保存/保存中」由 IPC 回执驱动。

**2. 设置存储（electron-store）**

- 技术：`electron-store` v11（见《技术栈.md》§3.12）；路径由库托管于 `userData`。
- 键空间（`SettingsSchema`，建议于 `src/shared/schema/settings.ts` 定义 Zod 并供 electron-store 的 `schema` 选项复用）：
  - `language: 'zh-CN' | 'en'`（F13 默认 `zh-CN`，不跟随系统解析）；
  - `defaultTemplateId: string`（F4 默认模板 id）；
  - `theme: { resumeFont; resumeAccent; resumeSpacing }`（F4 CSS 变量主题，与软件 UI 暗色正交，见《技术栈.md》§3.15）；
  - `updatePreference: 'silent-check' | 'manual'`（F14 默认 `silent-check`，仅启动/手动联网）；
  - `lastEditedResumeId: string | null`（启动恢复用）；
  - `appearance: 'light' | 'dark' | 'beige' | 'green'` + `appearanceMode: 'fixed' | 'system'`（F18 已定案 #16，M0 打令牌地基；见《技术栈.md》§3.15/3.15.1）；
  - `providers`（四服务商：deepseek/volcengine/openai/google）+ `temperature`（默认 0.7）+ `maxTokens`（默认 4096，硬上限 32768）（F12 S 批，见《技术栈.md》§3.9.2）；
  - `storage: { folderPath?; lastUsedAt? }`（F21 S 批，见《技术栈.md》§3.11.3）。
- 落码要点：设置写入须原子（electron-store 默认原子写）；`lastEditedResumeId` 在打开/切换简历时更新，崩溃恢复与启动恢复据此判定。

**3. 自动保存防抖 + 启动恢复**

- 自动保存：渲染进程订阅 `useResumeStore` 变更 → 500ms 防抖（与《项目功能.md》F3 历史栈防抖同窗，避免抖动）→ `ipcRenderer.invoke('resume:save', { id, data })`；主进程校验 Zod → 原子写 `<id>.json` → 回执 `saved` 驱动状态条。
- 启动恢复：应用启动（`app.whenReady`）后，渲染进程读 `lastEditedResumeId`；非空且文件存在 → **预加载该简历数据**（`loadResume`）但**不自动切视图**——界面默认停在「简历」欢迎页（`resumes-home`），用户从欢迎页主动进入编辑器（2026-08-07 用户拍板：启动先进欢迎页）；空/文件缺失 → 欢迎页（见《项目功能.md》四）。

**4. 数据安全三件套（v1.0 必做，已拍板 #6，落地不得降级）**

- **（a）崩溃恢复**
  - 机制：每次成功 `resume:save` 后，主进程在写入正式 `<id>.json` 前先写一个「临时锁文件」`userData/resumes/<id>.tmp`（写入中标记）；保存成功即删 `.tmp`。
  - 检测：应用下次启动时，`src/main/files/recovery.ts` 扫描 `resumes/` 下残留 `<id>.tmp` → 判定上次未正常退出 → 渲染进程弹「检测到未保存的编辑，是否恢复？」对话框，列出受影响简历。
  - 恢复：用户确认后，主进程用 `.tmp` 内容（或最近一份 `.bak`，见下）覆盖/提示覆盖 `<id>.json`；拒绝则保留 `.tmp` 供手动处理。
  - 落码要点：`.tmp` 写在前、`<id>.json` 写在后、成功后删 `.tmp` 三步须在同一 try/finally，确保原子性窗口最短。

- **（b）自动备份（保留最近 N 份 `.bak`）**
  - 机制：每次 `resume:save` 覆盖正式文件前，主进程先把**当前** `<id>.json` 复制为 `userData/resumes/<id>.bak.<timestamp>`（或滚动序号 `.<n>`，N 默认 5，可设 `SettingsSchema.maxBackups`）。
  - 轮转：备份数超 N 时，删除最旧的 `.bak`。
  - 用户可见恢复：设置页「简历管理 → 恢复备份」列出每份简历的 `.bak` 列表，选中即还原。
  - 落码要点：备份写在与正式文件同目录，便于整体导出 zip（见下）；`.bak` 同样带 `schemaVersion`，恢复时走 `migrate`。

- **（c）导出备份（设置页「导出全部数据为 zip」）**
  - 机制：`ipcRenderer.invoke('backup:export')` → 主进程用 `archiver`（或 Node 内置 `zlib` + 自写 zip；优先零依赖方案，若体积/复杂度高则引 `archiver`，须过《项目规范.md》4.7 G.2 依赖三问）→ 将 `userData/resumes/`（含 `.json` + `.bak`）与 `electron-store` 设置 JSON 打包为 `xiaomengresume-backup-<YYYYMMDD>.zip` → `dialog.showSaveDialog` 落盘。
  - 还原：`backup:import` 反向解包并覆盖（导入前自动先打一份 `.bak` 防误操作）。
  - 落码要点：导出不含 `userData/logs/`（日志另走 B 段「导出日志」）；不含任何 API Key 明文（Key 在 F12 走 `safeStorage`，不在本 zip）。

**2. 主进程读取**：四分区 AI handler 统一经 `getAiPrompt(key)`（`src/main/ai/prompts.ts`）从 electron-store 读 `aiPrompts.<key>`；缺失 / 空串 / 整体缺失 → 回退内置默认。首次启动与旧配置兼容；保存即生效（下一个 AI 请求自动取新值，无需重启）。

**3. 设置屏「AI 提示词」区状态机**（四条目各自独立）：

| 当前态 | 触发动作 | 下一态 | 副作用 |

- 四条目标签：语法纠正（F8）/ 自我介绍（F20）/ 简历润色（F7）/ 匹配打分（F9）；只读灰为稳定终态；「刷新」须二次确认防误触。

#### F11 最近简历列表（WP-T1 · T 阶段定案）

**1. 数据层（`src/shared/schema/resume.ts` + `src/main/files/resume-store.ts`）**

- **`ResumeSchema` 增可选 `meta`（仅增不改）**：顶层新增可选字段，**不破坏既有结构、`schemaVersion` 保持 `z.literal(1)` 不升**（与 F9 `targetJobDescription`、F19 `boundJobIds` 同策略），`migrate()` 现有 `case 1` 直通无需改动，旧 JSON 缺该字段 → Zod optional 自然兼容，**零迁移**：

```ts
// src/shared/schema/resume.ts —— 仅追加，不改现有字段
meta: z.object({
  createdAt: z.string().optional().describe('ISO 8601，主进程在首次创建时写入'),
  updatedAt: z.string().optional().describe('ISO 8601，主进程在 resume:save 时刷新'),
  lastOpenedAt: z.string().optional().describe('ISO 8601，主进程在 resume:open 时刷新'),
}).optional().describe('主进程写入的活动时间戳，仅增不改'),
```

- **写入时机（主进程承载，架构铁律 1）**：
  - `resume:save`：刷新 `meta.updatedAt = new Date().toISOString()`；`meta.createdAt` 若缺失则补写（首存即创建）。
  - `resume:open`：刷新 `meta.lastOpenedAt = new Date().toISOString()`；`createdAt` 缺失时同样补写。
  - `meta` 写入复用 `resume-store` 既有安全写（`.tmp` 锁）；`resume:open` 的 `lastOpenedAt` 刷新为轻量原子写、**不触发 `.bak` 轮转**（避免每次打开产生冗余备份），`resume:save` 仍走完整三件套链路（含 `.bak`）。
  - 旧简历 JSON 无 `meta`：`lastActivityAt` 回退取 `updatedAt` / `createdAt` / 文件 `mtime` 三者最大值（主进程计算，不污染磁盘）。

- **新 IPC `resumes:recent`（冻结于 `src/shared/ipc-channels.ts`）**：

```ts
// 调用（渲染 → 主，invoke）
ipcRenderer.invoke('resumes:recent'): Promise<Array<{
  id: string;                       // 简历 id（uuid，即 <id>.json 文件名）
  name: string;                     // 展示名：basics.name 优先，空则取侧栏别名/文件名兜底
  lastActivityAt: string;           // ISO 8601，= max(updatedAt, lastOpenedAt, createdAt)
  lastEditedAt?: string;            // = meta.updatedAt（展示主列）
  lastOpenedAt?: string;            // = meta.lastOpenedAt（可选副列）
}>>;
```

  - **主进程职责**：扫描存储基准目录（`<storageFolderPath>/`，见 §3.11.3；缺省回落 `userData/resumes/`）→ 逐份读 `<id>.json` → 取 `basics.name` 或别名 → 计算 `lastActivityAt` → **按 `lastActivityAt` 倒序**（从新到老）→ 返回数组（不读 `.bak`/`.tmp`）。
  - preload 暴露 `window.electronAPI.resumes.recent`。

**2. UI（最近简历列表屏）**

- **入口**：左侧栏「简历」分区选单已有卡片「打开或最近」（见《项目功能.md》四 / 线框 ⑩）；点击该条目 → 进入**最近简历列表屏**（即线框 ⑥ 的「最近」视图，见《原型线框图.html》分区 ⑥ 改动规格）。
- **列表屏形态**：每行 = **简历名称 + 最后编辑时间**（主）；可选副列「最后打开」（仅当 `lastOpenedAt` 存在且与 `updatedAt` 不同才显示）；按 `lastActivityAt` 从新到老排序。
- **操作（复用 F11 既有入口）**：每行提供「打开 / 复制 / 重命名 / 删除」——`打开` = `resume:open`（进入编辑器，刷新 `lastOpenedAt`）；`复制` = `resume:duplicate`；`重命名` = 仅改 `basics.name`（F11 重命名语义）；`删除` = `resume:delete`。无需新建独立 IPC，复用 F11 生命周期通道。
- **空态**：无任何简历时显示引导卡片，文案走 i18n（`resume.recent.emptyHint`），引导点「新建空白简历」。
- **排序语义（#20 定稿）**：以「最后活动时间 `lastActivityAt`」（打开或编辑任一动作刷新）排序，从新到老；列表主展示「最后编辑时间」（`updatedAt`），「最后打开时间」为可选副列。`meta` 字段与 `resumes:recent` IPC 承接该语义，简历 JSON 仅增 `meta` 顶层可选字段、`schemaVersion` 不升。
