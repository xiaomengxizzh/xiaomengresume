# F1 · 简历数据模型（地基）— M1

> 本文件由 `scripts/split_docs.py` 从《项目功能.md》拆分（2026-08-08 路由化定案）；真相源 = 本文档。

### F1 · 简历数据模型（地基）— M1
- **需求**：定义中英结构化简历，支持版本化 JSON 持久化与向后迁移。
- **实现框架**：`src/shared/schema/resume.ts` 用 Zod 定义 `ResumeSchema`，section 含 `basics / education / work / projects / skills / certificates / languages / summary`；富文本字段用 `RichText` 类型（Tiptap JSON，或降级 HTML）；每条目带稳定 `id`（uuid）；版本号 `schemaVersion` + 迁移函数（纪律见《项目规范.md》4.2）。
- **用户视角**：无独立界面（地基）。用户感知体现在：导入/迁移后数据正确落位、编辑不丢字段。

#### 字段集最终清单（WP-P1 · P 阶段定案）

> 本小节为《项目功能.md》F1「简历数据模型」的**字段集最终清单**，对应待拍板项 #10（《项目实现情况.md》§2.2）。由 WP-P1 起草，供 M1 在 `src/shared/schema/resume.ts` 直接落码（Zod v4 语法，子路径 `zod/v4`，见《技术栈.md》§3.6）。合并后本草稿删除。
>
> 设计要点：
> - 顶层 8 个 section：`basics / summary / education / work / projects / skills / certificates / languages`。
> - 富文本统一用 `RichText` 类型（Tiptap JSON `{ type:'doc', content:[...] }`，解析失败时降级为 HTML 字符串）。
> - 列表型 section（education / work / projects / skills / certificates / languages）每条目带稳定 `id`（uuid v4）。
> - 首字段 `schemaVersion: z.literal(1)`，附 `migrate()` 迁移骨架（纪律见《项目规范.md》§4.2）。
> - 中英双名：每个字段给出「中文字段名 / English 字段名」，英文命名即 F13 i18n key 候选（结构对称、禁硬编码中文）。

##### 0. 公共类型与默认值

```ts
// src/shared/schema/resume.ts
import { z } from 'zod/v4';
import { uuid } from 'uuid'; // 或 crypto.randomUUID()

// —— RichText：Tiptap JSON 文档，解析失败降级为 HTML 字符串 ——
export const RichTextSchema = z.union([
  z.object({
    type: z.literal('doc'),
    content: z.array(z.record(z.string(), z.unknown())), // Tiptap node 数组
  }),
  z.string().startsWith('<'), // 降级 HTML
]);
export type RichText = z.infer<typeof RichTextSchema>;

// 空文档默认值（Tiptap 空内容）
export const EMPTY_DOC: RichText = { type: 'doc', content: [] } as const;

// —— 日期：宽松 YYYY-MM（或 YYYY），允许 "至今" 语义由 endDate 为空表达 ——
const DateStr = z
  .string()
  .regex(/^\d{4}(-\d{2})?$/, '日期格式应为 YYYY 或 YYYY-MM')
  .or(z.literal('')) // 允许空串
  .optional();

// —— 列表条目统一带 id ——
const withId = <T extends z.ZodTypeAny>(shape: T) =>
  z.object({ id: z.uuid(), body: shape }).passthrough(); // 见下方各 schema 直接用 id 字段
```

> 说明：下列各 section 的数组条目直接在对象内声明 `id: z.uuid()`；`withId` 仅为示意，实际落码时每个条目 schema 显式含 `id`。

###### 2.9 layout（排版参数 · 单对象，2026-08-07 增补）

> per-resume 排版覆盖（F4 修订：模板预设 + 用户覆盖）。**覆盖链：简历 `layout` > 模板预设 > 全局设置初始值**；缺省 = 用模板预设值。用户在编辑器内调整即写入此处（M2 完整面板 / M1 顶栏最小控制）。**默认模板值保证 ATS 兼容，用户修改排版时分级提示（见 F4）**。

##### 4. 迁移骨架 `migrate()`

```ts
/**
 * 版本迁移入口：所有导入 / 反序列化先过 migrate() 再 parse。
 * 每次改 schema → 升 schemaVersion → 加对应 case（见《项目规范.md》§4.2）。
 */
export function migrate(data: unknown): Resume {
  const v = (data && typeof data === 'object' && 'schemaVersion' in data)
    ? (data as { schemaVersion?: unknown }).schemaVersion
    : 0; // 无版本号视为最旧（v0）

  switch (v) {
    case 1:
      // 当前版本：直通校验，返回强类型 Resume
      return ResumeSchema.parse(data);

    // 未来升级示例（M1 后如需新增字段）：
    // case 1升2时：
    //   case 2: {
    //     const v1 = migrate({ ...data, schemaVersion: 1 }); // 先回退到上一版
    //     const upgraded = {
    //       ...v1,
    //       schemaVersion: 2,
    //       // 新增字段补默认值
    //     };
    //     return ResumeSchema.parse(upgraded);
    //   }

    default:
      throw new Error(`Unsupported schemaVersion: ${String(v)}`);
  }
}
```
