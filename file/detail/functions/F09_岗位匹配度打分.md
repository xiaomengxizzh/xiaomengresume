### F9 · 岗位匹配度打分 — M3
- **需求**：简历 vs 岗位 JD 给综合分 + 维度分 + 改进建议。
- **实现框架**：数据模型增可选 `targetJobDescription` 字段（仅增不改）；`ipcRenderer.invoke('ai:match', { resume, jd })` → `generateObject({ schema: MatchScoreSchema })` 返回 `{ overall, dimensions[], suggestions[] }`；渲染进程卡片/进度条展示，建议可一键"去润色"。
- **用户视角**：粘贴一段「岗位 JD」→ 点「匹配度打分」→ 综合分 + 各维度分（卡片/进度条）+ 改进建议；点某条建议「去润色」→ 跳转到对应字段并触发 F7。

#### F9 匹配度打分落地点（WP-P3 · P 阶段定案）

**定位**：简历 vs 岗位 JD 给综合分 + 维度分 + 改进建议。**只打分、只给建议**，不自动改简历；建议可一键"去润色"（跳转 F7），由用户最终采纳（辅助编辑，呼应《项目功能.md》F9 与「人工掌控」）。

**1. 数据模型增字段（仅增不改）**

在 `ResumeSchema`（《项目功能.md》F1 / 《技术栈.md》§3.6）新增**可选**字段，**不破坏既有结构、无迁移负担**：

```ts
// src/shared/schema/resume.ts —— 仅追加，不改动现有字段
targetJobDescription: z.string().optional().describe('用户粘贴的岗位 JD，用于 F9 匹配度打分'),
```

保留 `schemaVersion: z.literal(1)` 不变（新增 optional 字段向后兼容旧 JSON）。

**2. MatchScoreSchema（Zod 草案，与 AI SDK v7 对齐）**

```ts
// src/shared/schema/match.ts
import { z } from 'zod/v4';

export const MatchDimensionSchema = z.object({
  name: z.string(),                       // 维度名，如"技能匹配""经历相关度""关键词覆盖"
  score: z.number().min(0).max(100),      // 0–100
  comment: z.string(),                    // 该维度短评
});

export const MatchSuggestionSchema = z.object({
  field: z.string(),                      // 关联简历字段（如 'summary' / 'work.0.bullets'），供"去润色"跳转
  text: z.string(),                       // 改进建议文案
  priority: z.enum(['high', 'medium', 'low']).optional(),
});

export const MatchScoreSchema = z.object({
  overall: z.number().min(0).max(100),    // 综合分 0–100
  dimensions: z.array(MatchDimensionSchema),
  suggestions: z.array(MatchSuggestionSchema),
});
export type MatchScore = z.infer<typeof MatchScoreSchema>;
```

AI 输出用 `generateObject({ schema: MatchScoreSchema })` 解析（见《技术栈.md》§3.9 结构化输出）；schema 即事实源，渲染进程按 `MatchScore` 类型消费。

**3. 主进程调用**

```ts
// src/main/ai/match.ts —— 薄封装，直接调 generateObject
import { generateObject } from 'ai';
import { getModel } from './sdk-helpers';
import { MatchScoreSchema } from '../../shared/schema/match';

export async function handleMatch(_e: unknown, { resume, jd }: MatchArgs) {
  const model = getModel();
  const { object } = await generateObject({
    model,
    schema: MatchScoreSchema,
    prompt: buildMatchPrompt(resume, jd), // 简历文本化 + JD 文本
  });
  return object; // 已是 MatchScore 类型
}
```

`buildMatchPrompt` 内部：把 `resume`（Zod 模型）序列化成纯文本 + 拼接 `jd`（来自 `targetJobDescription` 或用户即时粘贴），提示词要求"只评估、不生成简历内容"。

**4. 渲染进程展示 + 一键"去润色"**

- 展示：综合分用大号进度环/进度条（`overall` 0–100）；`dimensions[]` 用卡片列出各维度分 + 短评（`score` 进度条）。
- `suggestions[]` 列表：每条含 `field` + `text` + 优先级标签。
- **一键"去润色"**：点某条建议 → 跳转到 `field` 对应编辑器字段（定位/聚焦该字段）→ 预填该字段当前文本 → 触发 F7 润色流程（见 A 段），用户在 F7 对比框内**接受/放弃**。
  - 跳转用 Zustand store 的 `focusField(field)` 动作；`field` 路径须与 F1 schema 字段路径对齐（如 `work.0.bullets`）。
- 全程不自动写回简历，"去润色"只是把用户带到 F7 入口，最终内容由用户掌控。

**5. IPC 契约要点**

#### F9 匹配打分 R 批扩展（WP-R3 · R 阶段定案，T 批 WP-T2 多值扩展）

> 对应《项目实现情况.md》§2.1 WP-R3：AI 四分区之一「匹配打分」（F9 扩展）。待拍板 #13 按默认建议落定；#21（T 批）落定多简历多岗位消费方式。

1. **JD 来源 = 所选岗位 `requirements`**：`ai:match` 入参 `resumeId` 解析所选简历 `boundJobIds`；选中 `jobId` 时，主进程经 job-store 取该岗位 `JobSchema.requirements` 纯文本作为 JD。
2. **未选/未绑前端拦截**：`resumeId` 为空（未选简历）或所选简历 `boundJobIds` 为空（未绑岗位）时，「匹配打分」入口**禁用并提示「请先选择岗位」**（`ai.matchDisabledHint`）。
3. **`targetJobDescription` 兼容保留**：旧字段（仅增不改）不再于 UI 暴露录入，仅作兼容回退。JD 解析优先级：`resumeId+boundJobIds.requirements` > `targetJobDescription` > 拦截提示。
4. **提示词来源**：instructions 由 `SettingsSchema.aiPrompts.match` 提供（设置屏可编辑），缺省回退内置默认。
5. **IPC 增补（多值）**：`ai:match` 入参增 `resumeId: string` 与 `jobId: string`（所选简历 + 所选岗位，来自 AI 屏顶栏选择器）；`jd` 改为由主进程据 `resumeId`+`jobId` 内部解析，不再由渲染进程传入。
