# F5 · 导出（4 格式）— M2 / M3

> 本文件由 `scripts/split_docs.py` 从《项目功能.md》拆分（2026-08-08 路由化定案）；真相源 = 本文档。

### F5 · 导出（4 格式）— M2 / M3

- **需求**：一键导出简历，导出屏只呈现 4 个格式选项 + 目标位置，去掉其余配置项。隐私脱敏仍走 F16 顶栏开关，不占导出屏。
- **4 个格式选项（卡片式）**：
  1. **文字版 PDF**（v1.0 落地，**2026-08-10 B 档迁移修订**）：**隐藏窗口加载同源应用 export 模式（真实模板）→ `printToPDF` 单引擎**（与预览同一 bundle，构造级一致；`print/pdf.ts` `printAppToPdf`）。历史：2026-08-08 曾切 @react-pdf 纯代码（定案"printToPDF 依赖 GPU 合成、无 GPU 机器 100% 失败"），2026-08-10 网络调研（Chromium PDF 合成 = CPU Skia，无 GPU 依赖）+ 本地实测（Electron 43.3.0 disableHardwareAcceleration 下 1.9s 正常完成）实证推翻 → 回归 printToPDF（详见 `file/plans/2026-08-10_B档printToPDF单引擎迁移_执行计划.md`）。字体系统探测 + 子集嵌入（Chromium 自动）；版式由 `resume.layout` 驱动三套预设 + 主题色 + 头像，与预览同源对齐（`@page margin:0` + 模板 padding 全权，D1 拍板）。
  2. **图片版 PDF**（v1.1 落地）：`webContents.capturePage()` 按 `@page` 分页逐页截图 → 合成单 PDF，**候选依赖 `pdf-lib`**（纯 JS、过 G.2 三问，详见《技术栈.md》§3.8）。
  3. **图片格式**（v1.1 落地）：`capturePage` 逐页存 PNG（默认）/ JPG（可切换 + 品质参数）；多页 = 每页一文件（`简历名-页1.png`…）。
  4. **JSON 版本**（v1.0 落地）：当前简历 `ResumeSchema` 序列化（含 `schemaVersion`）落盘 `.json`，确定性、零 AI。
- **目标位置**：默认「简历存储位置」（F21 `storage.folderPath`）；未设置则系统下载目录；提供「选择文件夹」即时改；记忆用户上次选择（`SettingsSchema.export.lastFolder`，见 #22 默认建议）。
- **用户视角**：顶栏点「导出」→ 进入导出屏 → 选 1 个格式卡片 + 确认目标位置（默认已填上次目录）→ 点「导出」→ 进度条 → 落盘完成提示。v1.0 仅「文字版 PDF」「JSON 版本」可选（另两项置灰标注「v1.1」）；隐私模式开启时文字版 PDF 自动脱敏（见 F16）。

#### F5 导出落地点（WP-P2 · P 阶段定案 + WP-T3 修订）

**完整导出流程**（主进程统一承载生成/落盘，见《项目规范.md》五架构铁律 1；文字版 PDF 用主进程同源模板组件 `src/main/export/pdf/template.tsx`，版式参数与渲染端 `templates/shared/preset.ts` 同源，保证"模板=打印"一致）：

1. 渲染进程顶栏「导出」→ 打开导出屏（4 格式卡片 + 目标位置行）→ 调 `window.electronAPI.export.run({ format, folderPath?, pages?, privacyMode })`。
2. 主进程 `ipcMain.handle('export:run', ...)` 按 `format` 分流：
   - `textPdf`：主进程 `printAppToPdf`（`src/main/print/pdf.ts`）——隐藏窗口加载 `?export=1&resumeId=<id>&pages=all|first&privacyMode=0|1&language=zh-CN|en`（同源应用 export 模式，App.tsx D10 分支渲染真实模板 + data-redact）→ 轮询 `__exportReady`（30s）→ `document.fonts.ready`（3s 兜底）→ `printToPDF({ printBackground: true, preferCSSPageSize: true })`（30s 超时；失败重建窗口防打印队列污染）→ **pdf-lib 解析真实页数**（替代 D12 高度估算）；`pages==='first'` 走 `print-first-page-only` CSS 截断（export-root max-height 297mm）；**主进程侧 30s 超时兜底（超时不写盘）**。
   - `imagePdf`（v1.1）：按 `@page` 分页逐页 `win.webContents.capturePage()` → **`pdf-lib`** 合成单 PDF（候选依赖，见《技术栈.md》§3.8）。
   - `image`（v1.1）：逐页 `capturePage` → 存 PNG/JPG（按 `imageFormat`/`quality`）→ `简历名-页N.<ext>`。
   - `json`：`ResumeSchema.safeParse` 当前简历 → 序列化含 `schemaVersion` → 写 `.json`。
3. 目标目录优先级：显式 `folderPath` > `SettingsSchema.export.lastFolder` > `storage.folderPath`(F21) > 系统下载目录；落盘成功后回写 `export.lastFolder` 记忆用户上次选择。
4. 主进程经 `webContents.send('export:progress', { phase, ratio })` 回传进度；渲染进程显示进度条、禁用按钮。

**IPC 契约修订**（原 `pdf:export` 升级为统一 `export:run`，冻结于 `src/shared/`）：

```ts
// src/shared/ipc.ts（节选，修订既有段落）
export type ExportFormat = 'textPdf' | 'imagePdf' | 'image' | 'json'
export interface ExportRunArgs {
  format: ExportFormat
  folderPath?: string            // 缺省走 lastFolder > storage.folderPath > 下载目录
  imageFormat?: 'png' | 'jpg'    // 仅 image/imagePdf 相关；默认 'png'
  quality?: number               // 仅 jpg：0–1，默认 0.92
}
export interface ExportRunResult {
  canceled: boolean
  filePath?: string | string[]   // image 多页时为数组
  error?: string
}
// 进度事件：webContents.send('export:progress', { phase: 'render'|'capture'|'compose'|'write'; ratio: number })
// 通道名：'export:run'（取代原 'pdf:export'）
```

- 通道命名 `'export:run'`（取代原 F5 的 `'pdf:export'`）；参数/返回结构在 `src/shared/` 冻结，渲染进程经 `@electron-toolkit/preload` 暴露的 `window.electronAPI.export.run(args)` 调用。
- 导出过程渲染进程显示进度/禁用按钮，主进程无 UI，仅经进度事件回传状态。

**异常处理（2026-08-10 修订：@react-pdf 链路已退役，回归 printToPDF 单引擎）**：

- **textPdf 主进程 30s 超时兜底**：`printAppToPdf` 内就绪轮询/printToPDF 各 30s race，超时拒绝并**不写盘**（杜绝僵尸写盘/并发双写）；失败**重建打印窗口**（防单例打印队列污染，Electron 43.3.0 已修复 #51174 队列卡死，双保险）。
- 字体缺失/回退 → 不抛错（Chromium 系统字体 fallback，中文乱码概率低；`document.fonts.ready` 3s 兜底防挂死）。
- 用户取消目录选择 / 未选格式 → 返回 `{ canceled: true }`，不写文件、不报错。
- `export:run` 抛错 → catch 返回 `{ canceled: false, error: message }`，渲染进程 toast 提示「导出失败」。
- 隐私模式（F16）：`privacyMode` 经 URL query 传入 export 模式 → store → 模板 `data-redact` 全打码（预览/导出同源一致）。**已知缺口**：PDF 头像隐私导出（<Image>）——预览/导出已统一为 data-redact blur（2026-08-08 修复），不再有独立缺口。
