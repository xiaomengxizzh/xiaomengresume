## 一、文档体系规范

### 1.1 存储位置
- 所有 `.md` / `.html` 文档**一律存于 `file/`**，根目录不散放文档。
- 二进制/缓存产物（如 `deps-cache-reusable.tar.gz`）留根目录，不进 `file/`。
- `file/` 下**四个子目录**分工：
  - `detail/`（**正式子文档层**，2026-08-08 路由化定案）：`functions/`（功能详情按 F 编号拆分）· `logs/`（开发记录按月归档）· `api/`（API 参考，脚本自动生成）；
  - `draft/`（并行草稿，合并后删）· `plans/`（**里程碑执行计划存档，长期保留、不清理**，供后续 AI 检查/复盘回溯验收基准与决策记录；**每份执行计划必须含「用户旅程验收清单」专节**（管理者职责，见三 §3 角色卡 1），复盘时先对照该清单查"用户能否走通"而非"清单是否勾完"）· `rubbish/`（可清理归档：旧版本/被取代文档/过程文件）。

### 1.2 主文档结构与索引
- 主文档 **6 份**：《项目介绍》（是什么）·《项目规范》（本文，怎么做才对）·《技术栈》（怎么做）·《项目功能》（做什么）·《项目实现情况》（做到哪）·《项目日志》（改了什么）。
- **《项目介绍》《项目规范》《技术栈》《项目功能》开头必须建「索引」表**（章节 → 内容一句话）；新增章节须同步更新索引。
- **路由化（2026-08-08 定案）**：查找任何内容——**先读主文档索引/路由表 → 再按路由表翻对应子文档**；主文档承载**路由表 + 章节摘要 + 必须立刻知道的铁律常量**（如功能总览表、配色令牌、契约冻结清单），细节下沉 `file/detail/`。拆分规则：**功能详情按 F 编号、日志按月份**；技术栈/实现情况等**高频引用文档保持单文件**（超 100KB 阈值再评估路由化）。主文档与子文档**同步修改、同步提交**，子文档头部标注自动生成来源的禁止手写。

### 1.3 内容落点规则（内容进对应文件，不新建）

| 内容主题 | 写入文件 |
|---|---|
| 项目定位 / 信任承诺 / 用户痛点 / 开源配套 | `项目介绍.md` |
| 一切规范 / 纪律 / 治理规则 | `项目规范.md`（本文） |
| 技术选型 / 架构 / 依赖 / 导入方案 / 风险 | `技术栈.md` |
| 功能需求 / 实现框架 / 用户视角（F1–F16 + F18–F21） | `项目功能.md`（总览+路由表）+ `file/detail/functions/Fxx_*.md`（F 详情） |
| 已实现 / 准备实现 / 计划实现 / 待拍板 | `项目实现情况.md` |
| 界面线框 / 原型 | ~~`原型线框图.html`~~ / ~~`导航交互原型.html`~~（**2026-08-07 退役删除**，交互形态定案以 6 主文档 + detail/ 为准） |
| 一切进展流水（唯一日志归口） | `项目日志.md`（月度索引）+ `file/detail/logs/YYYY-MM.md`（按月条目） |
| API 参考（IPC 通道 / Zod 数据模型） | `file/detail/api/`（**由 `scripts/gen_api_docs.mjs` 自动生成，禁止手写**，见 §五.7） |
| 并行草稿（阶段闸门期间） | `file/draft/`（合并后删除） |
| 里程碑执行计划（M1/M2/…，产出即放入，执行完原位留档） | `file/plans/`（**长期保留、不清理**；真相源仍在 6 主文档，plans 供检查/复盘回溯） |
| 旧版本/被取代文档、过程文件、过期材料 | `file/rubbish/`（可随时清理） |

> 例外：只有出现**全新的功能分区**（现有文件都无法容纳）才新建 md，且必须：① 在 `项目日志.md` 登记；② 加入对应主文档索引；③ 归入 `file/`。**不新建孤岛文档、不重复造文件**。

> **1.3.1 三文档同步铁律（2026-08-08 归档新增 · 强制）**：任何新增或变更，若**超出《项目介绍》（是什么）、《项目功能》（做什么）、《技术栈》（怎么做）任一文档的当前描述范围**——包括新功能、新字段 / IPC 契约、新依赖、新架构决策、新模板 / 导出行为、交互形态变化等——**必须同步更新对应文档**（含开头索引表，见 §1.2），与代码 / 日志**同批提交**，禁止「代码先行、文档滞后」。仅修复既有行为且不改变描述范围的改动可豁免，但须在 G.7 自检 B 中显式标注「三文档无需动」及理由。缺漏由 `docs-tool.py selfcheck`（CH7 实现情况覆盖）与 G.7-B「关联文档已扫描」兜底。

### 1.4 日志归口
- `项目日志.md` 是**唯一开发记录归口**。每次实质性进展（新增/修改文档、确定决策、完成里程碑、修正错误）都追加一条**带日期**的条目。
- 新增文档/代码/决策前，先在此登记索引，避免文件散落。

### 1.5 引用规范
- 文档间互相引用一律用**相对文件名**（如《技术栈.md》），不写死绝对路径。
- 涉及根目录产物（如 tar.gz）时写"项目根目录"。

### 1.6 新文档准入
- 新 md 必须能挂到某个主文档索引下；否则先写进 `项目日志.md` 登记，再由主文档收录索引。

## 三、多 AI 并行协作规范（四角色工作流）

> 适用：指派**多个 AI 并行**完成同一阶段的规划或开发任务。铁律：**并行产出、串行合并**——任何 AI 不得与另一 AI 同时直接写同一正式文档。规划期（文档细化类，如 P/R/S/T/U 批）与执行期（代码开发类，M0–M5）同套四角色骨架：**管理者 M / 员工 W / 组长 L / 监督 S**；另设**机械执行者 E**（非工作流角色，见角色卡 5），承接确定性机械操作的委托。

**1. 为什么不能并行直写**：1.3 落点规则使同一分区多个并行任务落在同一文件（如 F1/F4/F7–9 都归《项目功能.md》），1.4 要求日志唯一归口；无文件锁与阶段闸门时，并行直写 = 互相覆盖、更新静默丢失、日志交错。文档体系按"单写者 · 顺序会话"设计，并发必须靠机制保障。

**2. 机制要素**：
- **阶段闸门**：阶段有「进入条件 / 工作包集合 / 退出条件」，**全部工作包合并验收通过、监督复核放行后才推进下一阶段**。
- **工作包（WP）独占产出**：每个 AI 只写自己独占的暂存草稿 `file/draft/<阶段>_<包ID>_<主题>.md`，不直接改正式文档。
- **组长唯一写正式文档**：验收 → 按 1.3 落点表合并 → 更新《项目实现情况.md》状态 → 追加《项目日志.md》→ 删除草稿。**《项目日志.md》与《项目实现情况.md》仅组长可写**。
- **段落级所有权**：同一正式文件被多包合并时，组长预先分配段落归属，按段合并、互不重叠。
- **四角色总览**：管理者（M）专职拆包计划与闸门定义；员工（W）只产独占草稿；组长（L）验收合并与状态收口（原「集成者」更名升级）；监督（S）独立复核放行。四角色职责互斥、同批内分离（详见 §3）。

**3. 四角色定义**

### 角色卡 1 · 管理者（Manager，代号 M）
- **职责**：① 接收阶段目标/需求；② 通读相关文档，做**可行性评估**；③ 制定**执行计划**（目标/范围/分包方式/依赖/验收标准）；④ 编写**工作包简报**（按 §4 简报模板，每包：输入文档清单、独占产出、合并归属、写作规范、自检清单）；⑤ 定义**阶段闸门**（进入条件/工作包集合/退出条件）；⑥ 启动分发。
- **执行计划必须含「用户旅程验收清单」（2026-08-07 M1 翻车复盘新增，硬要求）**：验收标准逐条拆成**用户操作步骤 → 对应 UI 控件/入口 → 对应落码工作项**的映射表，写入执行计划专节。规则：
  - 验收标准里出现"打开/新建/保存/切换/点击"等用户动作，映射表中**必须有对应的 UI 控件工作项**；映射不上的验收标准 = 计划漏项，发布计划前当场补齐；
  - 落码清单中的每一项也须能**反向映射到某个验收步骤**；无归属的落码项 = 计划冗余，一并清理；
  - 计划正文段落里的任何功能承诺（如"空则欢迎态"）**必须同时落成 checklist 条目**，不得只写在叙述句里（教训：非 checkbox 化承诺会在执行中静默蒸发且不进偏差登记）。
- **产出**：《阶段执行计划》+《工作包简报》（存 `file/draft/`）。
- **权限**：只写 `file/draft/` 的计划/简报；**不写任何正式文档、不写任何业务草稿**。
- **禁则**：不得兼任本批组长/监督（同批内职责分离）。

### 角色卡 2 · 员工（Worker，代号 W）
- **职责**：① 接收简报；② 按「输入文档清单」先读文档（G.1 先读文档再动手）；③ 只产出自己的**独占产出文件**（`file/draft/<阶段>_<包ID>_<主题>.md` 或代码）；④ 完成**自检清单**。
- **产出**：独占草稿/代码。
- **权限**：只写自己的独占产出；**不碰正式文档、不碰他人草稿、不写日志、不改线框/模拟器**。
- **禁则**：不得直接修改正式文档；不得在并行期与他人同时写同一文件。

### 角色卡 3 · 组长（Lead，代号 L）＝ 原「集成者」更名升级
- **职责**：① 验收全部工作包产出（对照各包自检清单）；② 按《项目规范.md》§1.3 落点表**段落级合并**进正式文档；③ 更新《项目实现情况.md》定案状态；④ 追加《项目日志.md》条目；⑤ 删除 `file/draft/` 草稿；⑥ 涉及界面形态/交互的改动按 §二 退役口径只落文档（线框/原型已于 2026-08-07 退役）。
- **产出**：正式文档变更 + 状态更新 + 日志条目。
- **权限**：**唯一写正式文档者**；《项目日志.md》《项目实现情况.md》仅组长可写。
- **禁则**：不得兼任本批监督（避免自审）；不得在监督复核未通过时推进闸门。

### 角色卡 4 · 监督（Supervisor，代号 S）＝ 新增角色
- **职责**：① 对组长**已合并**进正式文档的分包成果做**独立复核**；② 复核两维——**可行性**（技术/设计能否落地：依赖是否过 G.2、契约是否可冻结、是否与既有决策冲突）与**整体一致性**（与《项目规范.md》铁律 / 三步铁律 / 配色边界 / 架构铁律 / 已有文档内容是否一致、引用是否断裂、落点是否准确）；③ 输出《监督复核报告》（存 `file/draft/` 或 `file/rubbish/`）；④ 结论 = **放行**（闸门通过，进入下一阶段/里程碑）或 **打回**（附整改项，交组长返工）。
- **产出**：《监督复核报告》（含结论 + 问题清单）。
- **权限**：只读正式文档 + 写复核报告；**不直接修改任何正式文档**。
- **禁则**：不得兼任本批组长/员工/管理者；复核须基于**合并后的最新文档**，不得基于草稿。

### 角色卡 5 · 机械执行者（Executor，代号 E）＝ 2026-08-08 新增
- **定位**：承接**确定性机械操作**的委托角色，**无设计决策权**。单 AI 顺序执行时（非并行期），主 AI 可将机械步骤委托给子 agent，自己只验收结果——省上下文、省主链路心智。
- **职责**：① 接收明确指令（命令 / 脚本 / 预期结果，由主 AI 给全）；② 执行机械操作；③ 回报结构化结果（成功 / 失败 / 输出摘要 / 产出文件路径）。
- **可委托清单（机械操作白名单）**：
  - 跑测试 / 构建 / 冒烟（`pnpm test` / `pnpm build` / `XM_M0_SMOKE=1` / `XM_UI_SMOKE=1`）；
  - lint 确定性修复（规则明确、不涉及设计取舍的自动修复）；
  - 批量格式化 / 重命名 / 移动（纯机械变换，目标由主 AI 给定）；
  - 按既定模板生成骨架代码 / 测试夹具 / 示例文件（参数由主 AI 给定）；
  - 文档机械同步（把主 AI 给定内容按 §1.3 落点表写入对应章节，不自行改写内容）。
- **禁委托清单（红线，永远由主 AI / 组长亲自做）**：设计决策与架构取舍、契约修改（`src/shared/` 冻结区）、验收判定与放行、监督复核、写作规范制定、给子 agent 的指令本身。
- **权限**：只执行指令、只写指令指定的文件；**不得自主扩大范围、不得顺手"优化"**。
- **验收铁律（trust but verify）**：主 AI 对机械执行者产出**必须复核**（重跑命令 / 抽查产物 / 读 diff），**不得直接采信其自报"成功"**——"执行者说跑通了"不等于"真跑通了"（2026-08-08 定案，防自报式假验收）。

**4. 工作包简报模板**（发给每个 AI，缺一不可）：
1. 包 ID / 名称 / 所属阶段；
2. 输入文档清单（先读文档再写，见 4.7 G.1）；
3. 独占产出文件（`file/draft/…`）；
4. 合并后归属文件（按 1.3 表）；
5. 写作规范（相对文件名引用、不新建孤岛文档、不写日志、不碰他人草稿）；
6. 完成自检清单（格式合规 / 引用存在 / 无越界写入）；
7. **监督复核要点**：给出本包合并后监督须重点复核的条目（如 C3 不冲突、C4 索引同步、C6 术语统一；当本包落地到具体可执行项时，列对应 F/C 编号），便于监督按 §7 清单精准复核。

**双模式与模型档位（颗粒度升级，V 阶段定案）**：简报支持 **autonomous / guided 双模式**——
- **autonomous**（强模型 M/L 档位）：维持既有 7 要素即可，不追加字段，避免过约束；
- **guided**（轻/中档位，尤 W 角色弱模型包）：追加四字段——**产出大纲骨架**（章节结构照抄只填内容）/ **执行步骤**（动作→产出→完成判据，5–15 步）/ **内容点枚举**（每章硬性要点逐条）/ **反发散护栏**（明确不做什么）；
- 模式与「模型档位（轻/中/强）」由管理者（M）在简报头标注，分发时按档位分配模型；实际可用模型档位由用户/宿主决定，规范只定义抽象档位。
- 粒度平衡：guided 只给弱模型包；步骤上限 15 步（超限退回 M 重新分包）；内容点只列硬性要点、不给发挥空间。

**5. 临时目录规则（`file/` 下仅两个，均非正式文档）**：
- **`file/draft/` · 并行草稿区**：工作包产出、组长验收前的唯一落点；**并行结束、串行合并完成后必须删除**（见 §6 出口清单）。不进索引；1.3「不新建孤岛文档」约束的是正式文档，登记在案且会被合并删除的草稿不构成孤岛。

## 四、工程纪律（原《开发经验教训.md》，按里程碑排列，开工前通读对应章节）

### 4.1 M0 骨架
- **环境洁癖**：只用 pnpm（package.json 设 `"packageManager": "pnpm@<ver>"`）；`.gitignore` 第一天覆盖 `.npmcache/`、`*.log`、`dist/`、`electron-dist/`、`out/`；拒绝 `npx -y` 运行时下载；CLI 用绝对路径或 `pnpm run`。
- **主进程构建管线（M0 第一件事）**：Vite 只覆盖渲染进程，主进程 TS 要另起炉灶。**已定案 electron-vite**（评估报告 §5.1 选定，见《技术栈.md》3.2），M0 第一件事验证跑通；验证 `"type": "module"` + AI SDK v7（ESM-only）能正常 `import`。验收：`pnpm dev` 开窗、`pnpm build` 出 asar。
- **printToPDF 时序**：打印前必须 `await win.webContents.executeJavaScript('document.fonts.ready')` 再调 `printToPDF({ preferCSSPageSize: true, printBackground: true })`，否则中文乱码/排版错位。M0 用含中文字体的 HTML 验证端到端。
- **AI SDK 验证（主进程不是服务器）**：M0 在主进程 import AI SDK 跑一次 `streamText`，验证 ESM import、Key 从 safeStorage 读出、chunk 经 `webContents.send()` 推到渲染进程。
- **i18n 前移 M0**：立即建 `src/renderer/i18n/` + `zh-CN.json` / `en.json` 空壳并挂 Provider；**任何 UI 文案从第一行代码起走 `t('key')`，禁止硬编码中文字符串**；两语言 JSON 结构必须对称。

### 4.2 M1 编辑器
- **高亮 class 作用域铁律**：所有高亮 class 名统一定义在 `src/shared/constants.ts`（`HIGHLIGHT.GRAMMAR_ERROR` / `MATCH_FOUND`…）；标记/清除强制带 `className`，**禁止无参 `unmark()`**（会误清其他功能高亮），违例 PR 直接拒。
- **撤销统一栈（2026-08-08 修订）**：全局 Ctrl+Z/Ctrl+Y 全走 store 50 步历史栈（**含富文本聚焦时**）；Tiptap 禁用内部 UndoRedo（`StarterKit.configure({ undoRedo: false })`）——原「双栈隔离」存在双向污染（Tiptap 内部 undo 触发 onUpdate → 把撤销前状态压入 store 栈，行为不可预测），统一后语义单一可预测；代价 = 富文本撤销粒度字段级（整字段回退、光标回文档头，见《项目实现情况.md》§2.4 偏差 ⑪a）；500ms 防抖合并保留。
- **schema 版本化第一天开始**：`ResumeSchema` 首字段 `schemaVersion: z.literal(1)`；M1 写好迁移骨架 `migrate(data)` switch-case；每次改 schema → 升版本 → 加 case。

### 4.3 M2 模板与导出
- **"模板 = 打印"边界**：单一事实源是 **Zod 数据模型**，不是 DOM。编辑态（Tiptap contenteditable）与打印态（React 模板组件）是**两条渲染路径**，共享数据模型 + CSS 变量，DOM 完全不同。
- **@page 分页验证趁早**：第一套可用模板立即用 A4 三端验证：`@page { size: A4; margin: 15mm }` 一致、`page-break-inside: avoid` 中文字段跨页不硬截、`page-break-before: always` 章节分页正确；异常记入模板 README known issues。

### 4.4 M3 AI
- **薄封装，拒绝厚抽象**：每条 AI 能力 = 一个 IPC handler 直接调 `streamText` / `generateObject`；不要包"我们的 AI 服务层"；等出现 **3 处以上**相同样板再抽共享函数，**不要提前抽象**。
- **SDK v7 API 陷阱**：`system`→`instructions`、`fullStream`→`stream`。集中建 `src/main/ai/sdk-helpers.ts` 统一 import，所有 handler 只从这里取；豆包用 `createOpenAI({ baseURL: userEndpoint })`。
- **视觉模型双向守卫**：主进程收到 vision 请求先查模型，不支持直接 `throw new Error('VISUAL_NOT_SUPPORTED')`；渲染进程提示切换模型；设置页为视觉模型加 `✓ 支持图片/PDF 导入` 标签；非视觉模型时"导入 PDF"按钮置灰。

### 4.5 M4 导入
- **三步核对流不可跳过**：① AI 首轮映射 → ② 并排预览（原文 vs 结构化结果）→ ③ 逐段核对/修改 → ④ 确认写入。**UI 不提供"一键导入"按钮**——这是数据完整性底线，不是 UX 优化。

### 4.6 M5 打包
- **Defender 锁**：首次打包前把项目目录加入 Defender 排除或暂停实时扫描；打包卡 `packing` 超 5 分钟 = 99% 是 Defender。复用 `electron-builder-portable` 技能。
- **safeStorage Linux 降级**：`isEncryptionAvailable()` 为 false 时二选一——方案 A（推荐）退 electron-store 弱加密 + 一次性告警；方案 B 拒绝存 Key 每次启动手输。
- **electron-updater 与离线定位（已定案）**：采用 **electron-updater + GitHub Releases 更新源**（GitHub 即免费静态托管）；仅启动时静默检查 / 设置页手动检查才联网，核心功能完全离线。

### 4.7 全局纪律
- **G.1 先读文档再写代码**：每开始新功能先答三问——蓝图有无相关约束（如淘汰了 Paged.js 就别又引入）？需求清单有无已定义数据流（AI 必须走 IPC）？现有代码有无可复用？
- **G.2 依赖引入前自问三题**：需要原生编译吗（高风险）？会下载额外二进制吗（高风险，须离线缓存方案）？npm 超 2 年没发版吗（中风险，可能弃坑）？
- **G.3 验收与 git 协作模式（2026-08-07 修订 · 用户拍板：本机验收和 git 提交以后都由 AI 自行完成）**：环境特性不是应用 bug——沙箱 vite build 假报错、Bash cwd 偏差、printToPDF 无 GPU 挂起均按「沙箱假阳性」记录不处理（用户本机正常）。**验收方法（双轨制，2026-08-07 M1 翻车复盘修订 + 2026-08-08 UI 轨硬性脚本落地）**：里程碑收口后 AI 跑 `cd project && XM_M0_SMOKE=1 pnpm dev`（自动冒烟：窗口 / IPC / AI 流式 / 保存链路 / PDF，结果 JSON 打 stdout 自动退出）——**smoke 是后端链路验收依据（IPC 级），不覆盖 UI 入口/可操作性**；UI 级可操作性验收（入口存在、点击可达、状态条变化、重启恢复）走 **`cd project && XM_UI_SMOKE=1 pnpm dev` 一键脚本**（2026-08-08 新增，`src/main/ui-smoke.ts`）：真实 DOM 事件驱动「新建 → 编辑简历名 → 500ms 防抖自动保存 → 读盘验证 → `app.relaunch()` 真重启 → 启动恢复 → UI 值与磁盘双确认 → 清理退出」，结果 `UI_SMOKE_RESULT` JSON 打 stdout，任何一步失败进程退出码非 0；**涉及持久化/自动保存/启动恢复/路由跳转的改动，UI 轨必须 `XM_UI_SMOKE=1` 通过方可 commit**（防「钩子定义了没人挂载」类接线遗漏——2026-08-08 P0-1 useAutoSave 零调用翻车即 IPC 级冒烟测不出的典型案例）；GPU 受限仅豁免像素级视觉比对（排版/配色观感），不豁免入口/交互可操作性。四件套 + 里程碑专属段（如 M1 m1Save）为链路验收依据；PDF 等假阳性项登记口径。**git 方法**：沙箱 git 实测可用（已 init/commit，`git config` 项目级身份 `xiaomengresume contributors <dev@xiaomengresume.local>`）；每个工作单元收口后 AI 自行 `git add -A && git commit -m "<type>(<scope>): <subject>"`（message 走规范格式，禁 --no-verify）；`git push` 需 remote 已配置 + 本机凭据可用，无凭据时记录「push 待办」并告知用户（不影响后续开发）。所有路径用绝对路径。
- **G.4 渐进复杂度**：先写最简版本跑通端到端，再加模型选择器/prompt 模板/重试/流式优化；**永远不同时写"功能实现"和"架构抽象"**。
- **G.5 开源项目纪律**：信任承诺写进 README 首屏，界面文案不得与承诺矛盾（禁止"付费解锁/水印/限次数"字样）；M0 第一天建 CI；Issue/PR 模板先于第一个 issue；发布带 changelog + 三端产物 + 校验和；SECURITY.md 声明 safeStorage 加密、无遥测。
- **G.6 压缩恢复协议**：状态文件四要素（`goal` 目标 / `changedFiles` 已改文件 / `passedChecks` 已过检查 / `blockers` 剩余阻塞）+ 恢复读取顺序（①工作记忆 ②简报草稿 ③待拍板 ④已合并文档，**不凭记忆续接**）+ hooks 融合边界（SessionStart 只读 / PreCompact 只写状态层 / Stop 只提醒 / UserPromptSubmit 只注入，红线：hooks 禁写 `file/` 正式文档）。详见下方专节。
- **G.7 普通任务结构化自检（2026-08-07 定稿，用户拍板）**：**所有普通任务（非分包并行、单 AI 顺序执行）收尾交付前强制**跑一遍结构化自检清单（见下方专节），结果记入《项目日志》当日条目；与分包并行的监督复核（§三 角色卡 4）并行存在、互不替代。单 AI 自检 = 结构化自省，非独立监督，清单逐条核对以抓手滑。

#### G.6 压缩恢复协议（状态文件四要素 + 恢复顺序 + hooks 边界）

**状态文件四要素**（字段名权威，WP-V3 `state` 子命令同源生成）：
- `goal`：本会话/本批目标（一句话，含阶段与包集合）；
- `changedFiles`：已修改/已合并的正式文档段落（相对文件名 + 段落）；
- `passedChecks`：自检/复核结论（各包自检清单、监督报告结论；无则"—"）；
- `blockers`：待拍板项/未决/人工卡点（引用待拍板 # 编号；无则"—"）。
- 载体：写入 `.dev/G6-state.md`（docs-tool state 生成；2026-08-08 重构自 `.workbuddy/`）；并行期同步 `draft/` 合并执行清单。

**恢复读取顺序**（会话重开/压缩后第一时刻，**只读**、不凭记忆续接）：① 工作记忆状态（MEMORY.md 四要素）→ ② 简报/草稿（`draft/`）+ **里程碑计划（`plans/`，取当前/最近里程碑的验收基准与决策记录，检查/复盘必读）** → ③ 待拍板清单（《项目实现情况.md》§2.2）→ ④ 已合并文档（按 `changedFiles` 段落读对应正式文档）。读取后先复述四要素再动手。

**hooks 融合边界**（契约条款，宿主不支持则降级为 AI 自觉纪律，双态兼容）：
| 事件 | 职责 | 写权限 |
|---|---|---|
| SessionStart | 只读注入状态 + 简报路径 | 只读 |
| PreCompact | 压缩前刷新四要素到状态层 | 仅 `.dev/G6-state.md` |
| Stop | 只提醒不代写（剩 X 项未合并） | 不写 |
| UserPromptSubmit | 只注入不写 | 只读 |
- **红线**：hooks **禁写 `file/` 正式文档**（含《项目日志.md》《项目实现情况.md》）——防击穿「《项目日志.md》仅组长可写」单写者铁律。状态层（`.dev/G6-state.md`）是唯一允许的 hook 写入面。

#### G.7 普通任务结构化自检（2026-08-07 定稿 · 用户拍板 · 所有普通任务强制）

> **定位**：普通任务（非分包并行、单 AI 顺序执行）没有独立监督者，交付质量靠**收尾自检**兜底。与 §三 分包并行的监督复核（角色卡 4）**并行存在、互不替代**：分包任务走独立监督复核，普通任务走本自检。

- **触发**：**所有普通任务收尾、交付前强制**执行（改文档 / 写代码 / 出报告均适用）；任务中途完成即跑，不攒批。
- **产出物**：自检结果记入《项目日志》当日条目（轻量一段：「自检通过 ✅ …」或「自检发现 + 已修正」）；**不单独建报告文件**（避免污染文档体系）；重大任务可附在日志条目内详列。
- **自检清单**（逐条核对，任一不过 → 当场修正后重跑；无法修正 → 列入日志「遗留」）：

**A. 完成度**
- [ ] 用户请求的每一项都有明确结果（或显式标注未解决/待拍板，不静默遗漏）

**B. 文档一致性**（改文档时必查）

- [ ] 索引/总览同步（改 F 章节时功能总览、文档地图无断裂）

## 五、架构铁律与目录约定

1. **主进程统一承载 AI / 文件 / 打印 / 加密**；渲染进程纯 UI，API Key 永不落前端，天然无 CORS。所有 AI 调用经 **IPC → 主进程 → Vercel AI SDK（BYOK）**，渲染进程不直连供应商。
2. **Zod 简历数据模型为唯一事实源**；编辑态与打印态共享数据模型 + CSS 变量主题（"模板 = 打印"铁律）。
3. **编辑范式 = 混合（P0 已定案）**：结构化字段走受控表单；富文本字段（自我评价/工作/项目 bullet）用 Tiptap 仅作输入控件；预览/打印用 React 模板组件消费数据模型 + CSS `@page`。三选项对比见《项目功能.md》F2。
4. **目录约定**：
   - `src/shared/`：Zod schema、IPC 契约、类型（主/渲染进程共享）；
   - `src/main/`：Electron 主进程（AI / 文件 / 打印 / 加密 / IPC handlers）；
   - `src/renderer/`：React SPA（编辑器 / 预览 / 设置 / 导入向导）。
5. **AI 定位铁律**：F7/F8/F9 只做"辅助编辑"，**禁"一键生成简历"**。
6. **凭据与隐私铁律（2026-08-11 新增 · 安全扫描教训）**：
   - **凭据不落源码**：API Key / 令牌 / 密钥**只从环境变量或密钥服务读取**（应用运行时 = safeStorage keyring + 主进程环境变量）；源码、示例、测试**不得写入可用的凭据字面量**（可写占位符如 `sk-...`，不可写真实/可用 key）。
   - **禁本机绝对路径**：文档、代码、示例、测试**禁止写本机绝对路径**（如 `C:\Users\<用户名>\...`、`E:\tool\...`）——公开仓库会泄露用户名与目录结构；需提路径时用通用描述（`<用户目录>`、`<node安装目录>` 等）。已推送的绝对路径立即脱敏（2026-08-11 ai-capabilities.md 案例）。
   - **持续扫描**：CI 跑 gitleaks（`.github/workflows/security.yml`）；GitHub Secret scanning 应在仓库设置启用（见 SECURITY.md）。
6. **ATS 设计保证**：所有内置模板默认兼容 ATS（单栏 / 标准标题 / 系统或内嵌 OFL 矢量字体 / 文字可选），不设独立检查界面。
7. **API 文档自动生成（2026-08-08 定案）**：API 参考文档由 `scripts/gen_api_docs` **从 `src/shared/`（Zod schema + IPC 契约，唯一事实源）自动生成**，产物纳入 `file/`；**API 参考文档禁止手写维护**——手写必然与代码漂移（2026-08-08 定案，防契约变更后文档失同步）；每次 `src/shared/` 变更后必须重跑生成器，生成产物与代码同步提交。生成脚本本身随仓库版本控制。
8. **懒加载与代码分割铁律（2026-08-11 定案 · 内存与结构优化批 A1/A3）**：
   - **主进程重依赖一律函数内动态 import**：WASM 解析器（unpdf）、文档转换库（mammoth）、AI provider adapter（`@ai-sdk/*`）、PDF 库（pdf-lib）等**禁止顶层静态 import**——`externalizeDepsPlugin` 下动态 import 才是真延迟加载（解析/编译/WASM 初始化推迟到首次调用）；先例：`docx.ts` mammoth / `import/pdf.ts` loadUnpdf / `ai/client.ts` 三 provider / `print/pdf.ts` pdf-lib。
   - **渲染进程低频视图一律 `React.lazy` 拆 chunk**：AI 分区、导入向导、设置子页等低频视图必须 lazy（file:// 下动态 import 实测可用）；**编辑区高频核心交互（TipTap 富文本）保持同步加载**（防白屏/闪烁 + export 模式需同步渲染保 `__exportReady` 时序）；新增视图默认 lazy，除非论证为高频。
9. **大对象出堆铁律（2026-08-11 定案 · photo 转存批 B）**：任何大体积内嵌数据（base64 图片 >100KB、大数据块）**不得常驻 JSON / 自动保存 / 历史栈 / 全量序列化链路**——转存文件系统 + 引用（先例：`photos/` 资产目录 + `resume:read-photo` IPC + `data:`/`photos/` 双态渲染 + 导出重组内嵌自包含）。新增 schema 字段若承载大对象必须评审存储形态（内嵌 vs 引用）并评估对 stringify/写盘/备份/扫描链路的体积影响。
10. **隐藏窗口生命周期铁律（2026-08-11 定案 · 导出窗口 A2）**：低频隐藏窗口**用完即毁**（`destroy()` 回收 renderer 进程，process-model 依据；hide 只降级不回收）；新增隐藏窗口必须设 `backgroundThrottling: false`（防 hidden 节流拖慢就绪信号）；导出/打印类功能优先评估"最小渲染入口"（只加载模板所需，不加载编辑器/导入/AI）。
11. **渲染与内存意识自检（新增功能落地前过一遍，2026-08-11 定案）**：
    - ① 富文本/编辑器实例是否随条目数线性增长（N 个 ProseMirror 实例常驻——参照"预览不建实例"铁律，编辑区按需挂载）；
    - ② 每次变更是否全量深拷贝/序列化大对象（历史栈 50 步 × 对象体积；用结构共享 + 引用剥离）；
    - ③ 列表是否全量扫描/全量渲染（量大需索引缓存或虚拟化，`scanResumeFiles` 只读 `.json` 的先例）；
    - ④ 事件监听（`ipcRenderer.on` / `addEventListener`）是否随组件生命周期清理（防 listener 拽住窗口/闭包泄漏）；
    - ⑤ 预览/导出是否为同步快照且数据已就绪（printToPDF 前 await 字体/照片就绪，`__exportReady` 握手先例）。
12. **仓库卫生与二进制资产（2026-08-11 定案 · 仓库卫生批 A4）**：禁误操作创建命令残留目录/文件（先例：`-c`、`gh --version`、`.git.bak-*`、`.git.off`）；gitignore 防护模式随发现补充（`**/.git.bak*/`）；大二进制核验产物（PDF/PNG）统一入 `material/核验/`（gitignore 不入库），`material/` 只跟踪基准材料；临时脚本/备份（`*.bak`）用完即删或 gitignore。
13. **度量先行（2026-08-11 定案）**：性能/内存/结构相关改动**先量化基线再优化**——进程内存采样（`app.getAppMetrics` / `process.getProcessMemoryInfo` / `performance.memory`）、bundle 体积（chunk 分析）、写盘 IO（自动保存频率 × 对象体积）；防"未测量先优化"与"优化引入回归"（改后重跑 249 测试基线 + 相关 smoke）。
